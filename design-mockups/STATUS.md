### Deliberate deviations (where the mockup assumes a feature or data we don't have)

_Accepted by the product owner on 2026-10-11: everything listed here is in scope as-is. Of the features the mockups assumed, only the quiz game layer and fretboard presets were chosen for this pass. Streaks, XP and achievements stay visible, which supersedes the 2026-07-23 "hidden until v1.1" decision._

- **Auth**: email + password stay. There is no magic-link or Apple sign-in, so the "magic link sent" design is used for the password-reset confirmation. Role select offers teacher and student only, because parents are invited by their child's teacher.
- **Assignments**: tabs are Open / Completed / Cancelled because the data has no review step. No recording upload.
- **Student detail**: the Balance KPI is replaced by Lessons completed (there are no invoices).
- **Lesson detail**: no "Start live lesson" (there is no live mode). The audio player loops the whole track ("Loop") rather than A↔B.
- **Song form**: four difficulty levels (2×2 on desktop, four tabs on mobile). Required marks only appear on fields the server enforces. The mobile mockup designs only step I, so steps II–IV reuse the existing fields.
- **Student dashboard**: achievements are derived from existing data (8 milestones), not stored. Song of the Week stays, as a card under achievements. "Reschedule" opens an email to the teacher. "Start today's practice" opens the practice log.
- **Notifications**: filters are Lessons / Practice / System (no billing). The digest shows unread / today / this week instead of money collected. No inline accept/dismiss actions.
- **Settings**: tabs are Profile / Notifications / Integrations / API keys. Integrations shows only what exists: Google Calendar (connect/disconnect) and Spotify (built in). Stripe, Zoom, Apple Music and webhooks are not built.
- **Chord quiz**: XP, levels, daily goal, hearts and day streaks are built (2026-10-11), derived from `chord_quiz_attempts`: 10 XP per correct answer, 250 XP per level, a 40 XP daily goal, 5 hearts per free-play round (a teacher drill never ends early). Not built: the timer, hint/skip, the Hear / Build modes and the leaderboard (a leaderboard would expose other students' scores).
- **Admin**: MRR is replaced by songs; NPS and average session by students and teachers; churn % by "days quiet". No "Send report". Invites can be opened, not approved or resent.
- **Parent**: billing stays "coming soon". No "Reply to teacher": the teacher's email isn't visible to parents under RLS.
- **Fretboard**: "Save preset" is built (2026-10-11, `fretboard_presets`, owner-only RLS). Still not built: the "showing chords for <song>" chip (the explorer has no song context).
- **Mobile**: the bottom tab bar from the mobile mockups is replaced by the app's hamburger sheet. One app shell is used everywhere.
- **Nav**: Theory and Analytics stay hidden (they're stubs).

## Baseline audit: production before this pass (2026-10-10)

_Unchanged record of what production looked like before the implementation pass. Verdicts below describe production at the time, not the branch._

### How this was produced

- **Mockups.** Every `(Standalone).html` in `batch-01-core/` and `../claude design - mockups/batch-02-incoming/` was served over HTTP and screenshotted with Playwright 1.58 (Chromium). Desktop used 1440×1024 and mobile used 390×844, both full page.
- **Production.** Pages were captured with Playwright on the same viewports, signed in as the production test accounts (`+testteacher`, `+teststudent`). The capture was **read-only**: it navigated and scrolled each page so scroll-reveal sections render, and never submitted a form. The only non-GET requests it made went to the Sentry `/monitoring` tunnel. Detail pages used the first record on each list.
- **Comparison.** Each verdict comes from looking at the pair of screenshots, not from reading code.
- Batch-02 `Assignments Student/Teacher` are byte-identical to the batch-01 files and are counted once.

#### Limits: what this audit could NOT verify

- **No admin or parent account exists on production**, so Admin Dashboard (desktop and mobile) and Parent Dashboard went unchecked.
- **Onboarding** (student and teacher) can't be reached because both test accounts are already onboarded and `/onboarding` redirects to `/dashboard`.
- **The test student has no teacher, lessons, assignments or practice.** Student screens could only be judged on their empty states. Data-driven modules such as a streak or today's practice may be hidden when empty rather than missing. Those rows are marked _data-limited_.

### Cross-cutting gaps (apply to every in-app screen)

These account for most of the "doesn't look like the design" impression. Fixing them once in the shell or in shared components moves every screen.

1. **No top bar.** Every mockup has a top bar with global search, a `Week N` chip, a notification bell and a primary `+ New lesson` button. Production only has the user's name top-right, and search sits in the sidebar.
2. **Page header pattern.** Mockup: breadcrumb, then `Verb *accent*.` (roman title with one gold italic word and a full stop), a subtitle, and **Cancel / primary action top-right**. Production: an eyebrow and an all-italic title, with actions as uppercase text buttons **at the bottom of the form**.
3. **Form section cards.** Mockup: one header row (`I · EYEBROW Title`, a gold `n/m` counter and a collapse chevron) above a divider, with collapsible sections. Production: eyebrow and title stacked, the counter only, no divider and no collapse.
4. **Rich pickers downgraded to native controls** (the main reason forms look different):
   - student avatar pills became a `<select>` (Lesson Form, Assignment Form). The mockup's assignment form is multi-student, production allows a single student;
   - separate date and time fields became one native `mm/dd/yyyy, --:--` picker (Lesson Form);
   - the songs card grid became a searchable checkbox list (Lesson Form);
   - the recurrence toggle became a plain checkbox (Lesson Form);
   - filled-in fields are not tinted gold the way the mockup tints them.
5. **Avatars are all the same gold.** The mockups give each student their own colour, which carries identity across lists.
6. **Sidebar information architecture differs.** Mockup: Teaching / Students / Analytics (Song Stats, Lesson Stats) / Tools. Production: "Students" is renamed "People", the Analytics group is gone, and Practice Tools, AI Chat, Notifications and Settings are added.

### Suggested order of work

1. **Bugs B1–B3.** Small, visible, and B2 makes the mobile lesson list look broken.
2. **Shared form kit (cross-cutting 2–4).** Header with top-right actions, collapsible section header, student pill picker, split date/time. This upgrades Lesson, Assignment, Song and Student forms in one pass, and they were the screens that looked most off.
3. **Top bar (cross-cutting 1).** Search, week chip, bell and New lesson on every screen.
4. **Mobile layouts.** Lesson list cards, compact teacher dashboard, song-form wizard.
5. **Assignments.** Teacher quick-assign panel and student master-detail.
6. **Student dashboard.** Seed the test student with a teacher and data first, then re-audit before building.
7. **Not-built screens** (Settings Integrations, role select, magic link) are product decisions, not fidelity fixes.
