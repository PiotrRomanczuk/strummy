Lab — przeglądarka źródeł prywatnych danych (SNG-11, część 1)

2026-11-13 · gałąź feature/lab-local-data

Co zrobione

Nowa sekcja Lab (/dashboard/admin/lab) — przegląd prywatnego huba danych, który buduje song2logic (research/hub/build_hub.py) na Macu właściciela. Lab działa tylko lokalnie (gdy w .env.local jest PRIVATE_DATA_DIR wskazujący folder z manifest.json) i tylko dla admina. Na Vercelu zmiennej nie ma, więc strony zwracają 404, a w menu nie ma pozycji.

  • Lista źródeł: liczby z manifestu, każde źródło z opisem, liczbą wierszy, rozmiarem, datą i licencją, pogrupowane (dane osobiste, analizy, taby, zbiory porównawcze).
  • Źródło (/dashboard/admin/lab/sources/[id]): tabela surowych wierszy z wyszukiwaniem po wszystkich polach (bez wielkości liter i polskich znaków), stronicowanie po 50, cały wiersz jako JSON w oknie po kliknięciu numeru.
  • Czytnik JSONL / CSV (pola w cudzysłowach) / JSON (lista albo obiekt). Pliki czytane blokami po 1 MB: wyszukiwanie w 680 tys. wierszy Chordonomiconu ~1 s.
  • Odczyt wyłącznie plików z manifestu; id źródła z URL jest tylko porównywane z manifestem.

Jak przetestować

  1. Zbuduj hub (repo song2logic, PR #5): cd research/hub && python build_hub.py → ~/.cache/song2logic/hub/.
  2. W .env.local: PRIVATE_DATA_DIR=/Users/<ty>/.cache/song2logic/hub, potem npm run dev.
  3. Zaloguj się jako admin (baza dev) → w menu Analytics pojawia się Lab → lista źródeł z liczbami.
  4. Otwórz źródło, wpisz zapytanie (np. bez polskich znaków) → wyniki, licznik, stronicowanie; kliknij „Row N” → JSON całego wiersza.
  5. Zaloguj się jako uczeń/nauczyciel → /dashboard/admin/lab przekierowuje na /dashboard, w menu brak Lab.
  6. Usuń PRIVATE_DATA_DIR i zrestartuj → brak pozycji w menu, /dashboard/admin/lab = strona „nie znaleziono”.
  7. Nieznane źródło (np. /dashboard/admin/lab/sources/..%2F..%2Fetc) → „nie znaleziono”.
