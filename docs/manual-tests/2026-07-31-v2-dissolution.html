What was actually done

components/v2/ was not an abandoned parallel tree — it was the live implementation of onboarding, navigation, theory and the mobile primitives, imported by real routes. The migration it represented had already finished; what remained was a misleading label and the v1 corpses beside it.

So this change moves rather than migrates. 83 files, −1,372 lines, no behaviour change except one item flagged below.

Naming

Two components were both called AppShell and did different jobs. They stay separate — one decides which chrome a route gets, the other renders it — but the inner one is now NavigationShell, which says where it lives and what it wraps. The mount chain reads: 

app/layout.tsx
  → components/layout/AppShell         (route policy: none / dashboard-owns-its-own / shell)
      → components/navigation/NavigationShell   (Header + main + bottom nav + more-menu)

All 8 *V2 exported symbols lost the suffix, plus the *V2Props interfaces and OnboardingV2Boundary. Zero identifiers containing V2 remain anywhere in app/, components/, lib/, hooks/, schemas/ or types/.

Deleted — each verified unreachable from every route

  • components/navigation/ — Header.tsx (348L), ConnectionStatus, FontSwitcherDropdown, RoleBasedNav, plus Header.test.tsx
  • components/theory/ — TheoryChapterReader, TheoryCourseCard, TheoryCourseForm (superseded by the v2 equivalents; zero symbol consumers)
  • components/v2/primitives/StepWizardForm.tsx — a pure forwarding shim over components/shared/StepWizardForm (rule S7)
  • types/teacher-dashboard-v2.ts — zero importers, all 4 exported types unused
  • .claude/skills/mobile-redesign/ — see below

The one thing that could have undone this. The mobile-redesign skill instructed agents to create components/v2/<domain>/ files, and its progress tracker (docs/mobile-redesign/2026-03-16-PROGRESS.md) had already been deleted in ab49d95f. Running it would have failed on the missing tracker or rebuilt the tree that was just dissolved. It was the mobile redesign — which is now simply "the app" — so it was removed.

Also resolved

Two StatusBadge components shared a name with different contracts: one typed to the ServiceStatus enum with fixed config, one a generic pill taking a styleMap. The generic primitive keeps the name in shared/; the specific one became components/debug/ServiceStatusBadge.tsx. Duplicate component basenames went 5 → 1, and the survivor (primitives.tsx in four domains) is the domain-scoped pattern rule S3 explicitly permits.

How to manually test it

1 · The app boots and the shell renders

npm run dev

Sign in, then visit /onboarding and /ai — these are the routes that get the NavigationShell (the dashboard ships its own chrome).

Header, content and — on a narrow viewport — the bottom nav and more-menu all render as before. No console errors about missing modules.

2 · Theory works end to end (it was split across both trees)

Visit /dashboard/theory, open a course, open a lesson, then try new course, edit course and new lesson.

Course list, chapter reader and course form all render (these came from v2); the lesson form and course access manager also render (these were the two v1 components v2 never replaced). All five now live in one components/theory/.

3 · Desktop variants still lazy-load

Load /dashboard/theory at a wide viewport with the network tab open. The .Desktop variants are React.lazy chunks — the reason they looked "unimported" to a naive scan.

A separate chunk loads and the desktop grid layout appears (not the mobile card list).

4 · Onboarding wizard steps resolve

Visit /onboarding and walk through the steps.

Every step renders. The steps/ subfolder was briefly flattened during the move and restored — this is the check that it went back correctly.

5 · The label cannot come back

npm run check:structure

C3 version / age suffixed paths → ✓ none. A future v3/, legacy/ or deprecated/ directory warns on the first run.
