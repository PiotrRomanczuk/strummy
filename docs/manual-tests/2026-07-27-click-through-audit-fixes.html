Manual Test — click-through audit fixes

Date: 2026-07-27 · Branch: fix/teacher-audit-findings · Full report: docs/analysis/2026-07-27-teacher-student-click-through-audit.md

What this is

Every page, button and form in the dashboard was exercised in a real browser as a teacher, then a student, then an admin — with results verified in the database rather than taken from the UI. 33 findings: 30 fixed, 3 closed on inspection as not-defects.

Read this one first. Sign out never actually signed anyone out. The session is an sb-…-auth-token cookie; supabase.auth.signOut() in the browser only clears localStorage, so the cookie survived and middleware kept the session alive. On a shared machine the next person was still signed in. Please test this one personally — steps below.

Setup

  1. cd strummy && npm run dev (dev Supabase on uwh must be reachable)
  2. Sign in with the Dev quick login buttons on /sign-in, or manually: teacher@dev.local / test123_teacher, student@dev.local / test123_student, admin@dev.local / test123_admin

1. Sign-out actually ends the session (critical)

  1. Sign in as any role.
  2. Click the sign-out icon in the sidebar footer (or Sign out in the top-right menu).
  3. Expect: you land on /sign-in.
  4. Now type /dashboard in the address bar. Expect: bounced back to /sign-in?redirect=/dashboard.
  5. In DevTools → Application → Cookies, expect no sb-* cookie. This is the part that was broken — landing on /sign-in alone is not proof.

2. Lessons — filter, counts, pagination

  1. As teacher, open Lessons. Click the Completed chip. Expect: rows are returned (this used to return zero for every status) and the other chips keep their own counts instead of collapsing to 0.
  2. Check the header count is the real total, not the number of rows on screen. Expect: a pager beneath the list reading e.g. "Page 1 of 2".
  3. Click Older →. Expect: older lessons that were previously unreachable. As admin the same list shows all teachers and pages to 8.

3. Recurring lessons keep their settings (was data loss)

  1. Lessons → + New lesson. Pick a student, a title, a date.
  2. Set Duration 60 min, Format: Video call, add notes.
  3. Tick Repeat weekly → Create lesson.
  4. Open any of the created lessons. Expect: 60 min, Video call and the notes are all present. Previously every repeated lesson was saved with a null duration and format and a forced SCHEDULED status, silently discarding what you entered.

4. AI works again

  1. AI Chat → ask "List three beginner guitar warm-ups." Expect: a real answer.
  2. If the provider fails, expect a visible red error in the bubble — not a blank reply. (Silent empty bubbles were the old behaviour.)
Billing note. OpenRouter retired the :free endpoints these models were pinned to, so the fix resolves to the paid tier. Set OPENROUTER_ALLOW_PAID=false to keep the old behaviour and have it fail loudly instead.

5. A student can no longer mint an API key (security)

  1. Sign in as student → Settings.
  2. Expect: no "API Keys" section at all.
  3. Optional, proves the server check rather than the hidden UI — in the console: 
    await (await fetch('/api/api-keys',{method:'POST',
  headers:{'Content-Type':'application/json'},
  body:JSON.stringify({name:'x'})})).json()
    Expect: 403 "Only teachers and admins can create API keys".

6. Student-facing copy and naming

Where Expect
Student → My Assignments (with an overdue item) "1 overdue assignment — worth catching up on." (not "needs a nudge")
Student → open an assignment Header shows only the due date — not "for <your own name>"
Student → a completed assignment The "tick off what you've practised" instruction is gone once it's handed in
Student → open a lesson Reads "with Sarah Mitchell" (their teacher), not their own name
Student sidebar "Song Library" (it lists the whole studio library) + a "Notifications" entry

7. Visual / correctness spot checks

  • Any dropdown (e.g. AI Assistant → Student): the highlighted option is a soft gold, not red. Time Period / Email Type show their value immediately on load rather than as an empty stub.
  • Teacher dashboard → Needs attention: students with no practice read "never" / "no practice logged yet" — no 999d.
  • My Repertoire: dates render and the browser console has no hydration error.
  • AI Chat: only one sidebar item highlights; all five prompt chips are visible; no nested-button warning in the console.
  • Admin topbar badge: shows the real host (192.168.1.75:55321). It used to print localhost:54321 — the production port — regardless of the real target.
