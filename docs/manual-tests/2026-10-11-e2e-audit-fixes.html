Tests that could not fail, now real

  • student/assignments-interact: status tests looked for testids that did not exist and always skipped. Added assignment-status-<target>. One lifecycle test drives not_started → in_progress → completed on the seeded row and checks the DB and a reload. The student cannot cancel.
  • student/lessons-read: real isolation (another student's lesson is absent from the list and does not render at its URL), a role-based delete check, and the lesson's song asserted.
  • student/songs-read: the search used the top bar's global search instead of the list's title filter; it now narrows to the seeded song. The detail and UG link are asserted.
  • teacher/lesson-song-status: clicks the stepper, checks the DB and aria-pressed after reload. aria-pressed was added to the stepper.
  • teacher/assignments-crud lifecycle and users-management A6.4: stale "Coming Soon" skips replaced by working tests on the current forms, plus a teacher-redirect check.
  • teacher/lessons-crud: delete goes through the UI (trash → Cancel keeps → Confirm removes), not the API.
  • teacher/backfill-at-risk: the "drops out" filter matched retired copy; the empty-state branch asserted copy that no longer exists. Now desktop-only, because the card is hidden md:block.
  • cross-role/access-control C2, parent/dashboard nav (by href, not the renamed label), integration/workflows (targets the E2E student, cleans up by id, dead table-based tests removed).
  • mobile/mobile-responsiveness: the phone day-spine test now checks the phone composition; 44 px fails instead of warning; iPad measures <main> on purpose.
  • Fretboard phone specs: openFretboard expands Controls before waiting for hydration. The mute-button proof was inside the collapsed rail, so every phone run timed out. New test for the collapsed state.
  • Removed: teacher-full-journey, student-full-journey, student-learning-journey. They were if-guarded, their cleanups never matched, and they leaked rows. Each phase is covered by a domain spec.
  • Cleanup: song-detail-duplicate/quick-assign deleted as the student and leaked; 1555 leaked songs were removed from the dev stack. song-cover, lesson-duration-format, assignment-target-submission and lessons-crud now delete in afterEach. notifications/prefs restores the original values instead of deleting.

How to test manually

  1. Song wizard: phone width, /dashboard/songs/new, tap step 4, tap Create. Expect Canto I with "Please fill out this field". Fill the title and artist; Next moves on.
  2. Bell: with unread notifications, the top-bar bell shows a red count (9+ above nine). Mark all read, reload, and the badge is gone.
  3. Return-to: sign out, open /dashboard/lessons/<id>, sign in, and you land on that lesson. /sign-in?redirect=//evil.com lands on /dashboard.
  4. Health dot: a student last practised 10 days ago shows in Needs attention but with a green dot; at 14+ days the dot is red and their profile shows the at-risk banner.
  5. Goals: a student who picked goals in onboarding shows "Learn classic songs" etc. on their profile, not keys.
  6. Fretboard (phone): open Controls; the Style row is there; Mono changes the board.
  7. Notification prefs: toggle a preference off and on quickly, reload, and the state matches the last toggle.
