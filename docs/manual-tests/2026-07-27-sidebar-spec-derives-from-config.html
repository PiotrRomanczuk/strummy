Sidebar spec: six stale assertions, zero app bugs

Date: 2026-07-27 · Branch: fix/api-uuid-validation · Found by: the local E2E run against the dev stack

Three E2E sidebar failures, one per role — all of them the test asserting a shape the app had deliberately moved away from. No app bug. (The real bug from the same run is in 2026-07-27-api-uuid-guard.html.)

What was wrong

Three sidebar failures, one per role. All three were the spec asserting a sidebar shape that had been deliberately changed, each with a dated comment in menuConfig.ts explaining why:

Assertion Reality
admin: AI Assistant hidden SHOW_AI_FEATURES = true — AI nav is intentionally on
teacher: Skills hidden revealed 2026-07-22 (CHT-2)
student: My Songs visible relabelled to Song Library (SNG-6)

Three more stale assertions never even ran, because each test died at the first one: admin Fretboard/Calendar hidden, and student My Repertoire hidden — all three are visible now (revealed 2026-07-19). Six stale assertions, zero app bugs.

Why it was rewritten rather than patched

Patching six labels would just reset the clock on the same drift. The completeness check now derives from sidebar.helpers — the very module the sidebar renders from — so reveals and relabels flow through automatically, while a genuine rendering bug (config declares an item, the DOM disagrees, or a stray item appears) still fails.

A config-derived test can't catch a wrong config, since it agrees with itself. So the spec also keeps explicit cross-role guards that hold regardless of config — a student must never be offered Students, Skills, Health Monitor, Logs or Cohorts. Those are the assertions worth breaking a build over.

How to verify

1. The spec is not vacuous

A set-equality test can pass by comparing two empty sets, so this was proven to fail on a real divergence. Add a nav item the DOM won't have and watch it break: 

# in components/navigation/menuConfig.ts, inside getTeacherGroups() Teaching items:
{ id: 'stray-probe', label: 'Stray Probe', icon: BookOpen, path: '/dashboard/stray' },

npx playwright test tests/e2e/dashboard/sidebar.spec.ts \
  --config=playwright.local-3100.config.ts --project="Desktop Chrome"

Expect 2 failed (admin + teacher) naming "Stray Probe". Revert, re-run, expect 5 passed. Verified — do not use an id listed in CORE_LOOP_HIDDEN_ITEMS (e.g. logs) for this probe: it gets filtered out and the test correctly stays green.

2. If the run suddenly fails at login

Symptom: tests time out on page.waitForURL('**/dashboard**') and the run takes minutes instead of seconds. That is not the sidebar — it is the auth_rate_limits throttle after repeated logins. Reuse of tests/.auth/*.json normally keeps it to one login per role, so do not delete those between runs. To clear it: 

KEY=$(grep '^SUPABASE_LOCAL_SERVICE_ROLE_KEY=' .env.local | cut -d'"' -f2)
curl -X DELETE "http://192.168.1.75:55321/rest/v1/auth_rate_limits?operation=eq.login" \
  -H "apikey: $KEY" -H "Authorization: Bearer $KEY"

If an account also shows a non-null locked_until, reset profiles.failed_login_attempts = 0 and locked_until = null for it.
