The demo journey — what a recruiter actually hits

Date: 2026-08-17 · Branch: fix/demo-journey · Surface: https://strummy.online (production) · Path: landing → "Try the demo" → "Try Demo Account"
Headline. The demo is not merely empty — it is an unescapable dead end. A visitor fills in a five-minute setup wizard, clicks Finish setup, and gets Failed to update profile. Every route then redirects back to the wizard. There is no way into the app.

1. The walkthrough

  1. Landing page → Try the demo → goes to bare /sign-in. It does not start the demo: the auto-fill only fires on ?demo=true, so the visitor must spot a second button.
  2. Try Demo Account → signs in as sarah@strummy.app → /onboarding.
  3. Choosing "I teach guitar" expands a 3-step wizard into 6 steps, ~5 minutes.
  4. Step 4 asks for student emails — in production these are real invite emails. Skipped.
  5. Finish setup → Failed to update profile. Reproducible on retry.

2. Root cause

From production runtime logs at the moment of the click:

[onboarding] profile lookup failed
PGRST116 — "Cannot coerce the result to a single JSON object" · "The result contains 0 rows"

saveOnboarding resolves the caller via profiles.user_id = auth.uid() and finds nothing. Confirmed against the production database:

auth_uid                              email              profile_id  is_teacher  onboarding_completed
8e639ae5-f7ea-43bb-9317-d70ad830f78c  sarah@strummy.app  (null)      (null)      (null)

Exactly five auth users in production have no profile row, and they are precisely the five demo accounts (sarah@, emma@, carlos@, lily@, james@), all created 2026-07-28. seed:demo was run far enough to create the auth users and then died before writing profiles.

Real sign-ups are unaffected: 9 of 9 real users have profiles, and trigger_handle_new_user is present and healthy on auth.users.

3. What changed in this PR

FixWhy it matters
Onboarding heals a missing profile (app/actions/onboarding.ts) The lookup moved to maybeSingle(); when no row exists the action now creates one, mirroring what the sign-up trigger writes. This action was the single place that could have rescued such a user and instead returned a generic error — turning a recoverable state into a dead end.
Step counter derives from one source (Onboarding.Steps.tsx + 4 step components) Each step hardcoded "Step N of 5" while the rail counted the real array (6). Both totals rendered on screen simultaneously for the entire teacher flow.
"Try the demo" actually starts the demo (Landing.Nav.tsx) Now links to /sign-in?demo=true. Previously indistinguishable from "Sign in".

4. Still required — a data fix this PR cannot make

The code change stops the dead end, but the demo is still empty until the seed runs. The intended remedy is one command, documented in lib/auth/test-account-guard.ts as the idempotent reset:

# from repo root, with production credentials
set -a; . ./.env.production.local; set +a
npm run seed:demo -- --yes

It creates Sarah Mitchell plus Emma Johnson, Carlos Reyes, Lily Park and James O'Brien — the exact personas in the landing-page hero — with historical lessons, songs and assignments. Its deletes are scoped to those demo students only. Production baseline before running: 11 profiles · 76 lessons · 500 songs · 0 assignments.

5. How to verify manually

The demo path

  1. From the landing page click Try the demo — it should land on /sign-in?demo=true and sign in on its own, with no second click.
  2. If the seed has run, you land on a populated teacher dashboard as Sarah. If it has not, you land on onboarding — but the wizard must now complete rather than erroring.
  3. Walk the teacher branch and confirm the header eyebrow and the left rail always show the same total.

The self-heal

  1. On a dev stack, delete a test user's profiles row while leaving auth.users intact.
  2. Sign in as them and complete onboarding — it should succeed, and a fresh profile row should exist with onboarding_completed = true.
  3. Server logs should carry [onboarding] no profile row for authenticated user — creating one.

Automated

npx jest components/onboarding/Onboarding.test.tsx

Includes "agrees with itself about how many steps there are", verified to fail when the hardcoded eyebrow is reintroduced (Expected: 1, Received: 2) rather than passing vacuously.

7. Deployment note

None of this reaches users until a release runs. Production last deployed Aug 15. Two separate causes were found and both are now cleared:

  • Builds were failing. Every recent build errored with Module not found: Can't resolve '@vercel/turbopack-next/internal/font/google/font', preceded by Google Fonts fetch warnings. The same build succeeds locally, and a plain redeploy on Vercel now succeeds — the fetch failure was transient infrastructure, not a code defect. Worth watching: if it recurs, self-hosting the three fonts removes the build-time dependency on Google entirely.
  • The branch model changed. Pushes to main now produce Preview deployments, so the two-stage model documented in CLAUDE.md is switched on and production is the release branch. Shipping is now a main → production PR.
