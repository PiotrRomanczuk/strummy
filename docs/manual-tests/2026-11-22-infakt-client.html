inFakt API client

What was built

  • lib/invoicing/: a standalone client for the inFakt API v3. It imports nothing from Strummy, only zod and node built-ins.
  • Operations: find or create a private-person client, issue a proforma or VAT invoice (one service line, transfer, due date from the payment term, exemption reason for the zw rate), get by id or uuid, list with URL-encoded filters, create a quick-payment link, mark as paid.
  • isPaid reads status === "paid" only.
  • Typed errors for 401, 404 and both 422 shapes; a 422 on bank_account / bank_name reads "No bank account configured in inFakt". Network failures and non-JSON bodies come back as results, never thrown.
  • Without an API key the factory returns skipped, so dev and CI cannot issue an invoice.
  • verifyInfaktSignature: HMAC-SHA256 of the raw body, constant-time comparison.
  • An architecture test that fails when anything in lib/invoicing/ imports from outside it.

Deliberately not wired yet

  • No call from lib/services/billing/ or the sale: nothing in the app changes for users.
  • No webhook route, no daily reconciliation, no "Ponów" button.
  • No real HTTP call to inFakt was made, neither sandbox nor production. All responses in tests are synthetic.

Pointing it at the sandbox later

When the wiring PR exists, set the key in the environment of the shell or Vercel, never in a file in the repo:

INFAKT_API_URL=https://api.sandbox-infakt.pl/api/v3
INFAKT_API_KEY=<read from the password manager at run time>

Build the client with createInfaktClient({ apiKey: process.env.INFAKT_API_KEY, baseUrl: process.env.INFAKT_API_URL, documentKind, vatRate, exemptionReasonId, paymentTermDays }). A missing key gives skipped. The sandbox needs a bank account on the inFakt account, or issuing fails with the "No bank account configured in inFakt" error.

Unverified against the live API

  • The client search filters (q[email_eq], q[first_name_eq] ...) and the list envelope { entities: [...] }.
  • That vat_exemption_reason sits on the invoice, not on the service line, and that prices are sent in grosze.
  • The quick-payment response field payment_link.

These are checked on the first sandbox run in the wiring PR.
