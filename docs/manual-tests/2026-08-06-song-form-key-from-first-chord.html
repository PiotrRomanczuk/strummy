Key derived from the opening chord

Date: 2026-08-06  ·  Branch: feature/song-form-key-from-first-chord  ·  Surface: the Ultimate Guitar import on both song forms

What was built

The Ultimate Guitar import now also fills the Key dropdown, derived from the chord the tab body opens on. It shows up as a Key row in the “Found” preview alongside the other detected fields, and is applied with them.

Why the body's first chord, not the chord list's

UG's Chords block is not in order of appearance. On the page used to build this, the list begins Bmadd4 — a chord that only occurs in the bridge — while the song itself opens on C. Reading the key off the chord list would give Bm for a song in C. So the key comes from the first chord-only line of the tab body; the chord list is only a fallback for pastes with no body.

Chord → key

Chord Key Rule
C C bare root → major
Am, Am7 Am m → minor; extensions ignored
Bmadd4 Bm ditto
Cmaj7 C maj is not minor
Csus4, G5 C, G no quality → major
D/F# D slash bass ignored
Bb, Ebm A#, D#m flats respelled — the key dropdown offers sharps only

How to test manually

  1. npm run dev, sign in via Dev Quick Login → Admin
  2. Go to /dashboard/songs/new, expand Paste from Ultimate Guitar
# Do this Expect
1 Paste a UG page whose tab opens on a plain major chord, press Parse A KEY row appears in the preview showing that chord's root
2 Press Apply to form The Key dropdown in Performance details moves to that key; the Preview panel's KEY also updates
3 Use a page whose tab opens on a minor chord (e.g. Am) Key becomes Am, not A
4 Use a page whose first chord is a flat (e.g. Bb) Key becomes A# — a value the dropdown actually offers
5 Change the Key by hand after applying Normal dropdown behaviour; the import does not overwrite it again
6 Paste something with no chords at all (e.g. only Difficulty:Novice) No KEY row in the preview; the form's Key is left alone

Known limitation (by design)

A song's first chord is a hint, not analysis — plenty of songs open somewhere other than the tonic, and this will get those wrong. It is a starting guess that saves a click on the common case; correcting it is one dropdown selection. Nothing downstream treats the imported key as authoritative.
