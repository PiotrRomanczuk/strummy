What was done

The public “Try the demo” cohort (*@strummy.app, profiles.is_development = true) stays on production, but a real user (owner: admin + teacher) no longer sees those fictional people anywhere. Five restrictive SELECT policies (profiles, lessons, assignments, student_repertoire, practice_sessions) AND with the existing permissive ones, so rows only disappear, never appear. A viewer whose own profile is is_development (demo teacher/student, every RLS-test seed user) is exempt. Two SECURITY DEFINER helpers (is_development_viewer(), is_demo_profile(uuid)) do the lookups without re-entering RLS — a plain subquery recursed through profiles_select_own_teacher (42P17). Also fixed: bare /worktrees/ in jest.config.rls.ts / jest.config.integration.ts made both suites find 0 tests from inside a worktree.

Update 2026-10-20 (evening): participant exemption

The first version hid a lesson/assignment whenever either side was a demo profile. On the dev stack the shadow-claim E2E creates a real student under "any teacher" (always is_development there), and that student lost their own lessons. The policies on lessons, assignments, student_repertoire and practice_sessions now also pass when the viewer is a participant (current_profile_id() equals teacher_id / student_id). Your own rows are never hidden from you. On production no real user shares a row with a demo profile, so nothing changes for the owner.
