Next.js security upgrade 16.4.3 to 16.4.5

2026-11-24

What changed

  • next 16.4.3 to 16.4.5 (range in package.json raised to ^16.4.5); package-lock.json updated by npm. No other dependency was touched.
  • eslint-config-next deliberately stays at 16.3.3 (see below). No application code, proxy.ts, next.config.ts or CSP changes were needed; this is a patch release inside the same minor line.

Advisory

npm audit --omit=dev reported seven moderate advisories on next, all affecting <=16.4.4 and fixed in 16.4.5 (the lowest patched release; 16.4.6 is the current latest):

Advisory Topic
GHSA-mfr8-8qww-v76h Root params disclosure, use cache through unstable_cache()
GHSA-vc7v-qv4w-wrv8 Cache leak across root params in nested use cache
GHSA-7qx7-33qx-rqx2 SVG rejection bypass in image optimization
GHSA-f3mh-rxg3-f5g2 HttpOnly cookie exposure on Edge runtime routes
GHSA-pc58-hwjq-p385 Cross-client response injection (self-hosted)
GHSA-rhh4-g77r-r9qj Cross-user cache disclosure with binary arguments
GHSA-vvgp-ww4w-46vf Cache poisoning of shared fallback shells

After the bump npm audit --omit=dev no longer lists next. The dev server prints no vulnerability banner.

Why eslint-config-next was not bumped

Bumping it to 16.4.x makes npm resolve eslint-plugin-react-hooks 7.1.1 (instead of the nested 7.0.1). That version adds new rules that turn into 13 lint errors in existing code (set-state-in-effect, immutability, refs, purity). The same will happen to the Dependabot bump of eslint-config-next, so it needs its own change that fixes or configures those rules.
