Findings surfaced by the E2E work

  • Teacher-role can't add students. /api/users POST intends teachers to create students ("Teachers can only create students" guard) but inserts the shadow profile with the RLS session client while an unused createAdminClient() sits right there; dev's "Teachers can create student profiles" RLS policy uses has_role('teacher') (a user_roles lookup) which the profile-flag teacher account doesn't satisfy → 500 RLS violation. Works as admin (the studio owner is admin+teacher, so real usage is fine); the spec logs in as admin and flags this. Fix candidates: insert via the admin client after the existing authz guard, and/or reconcile the dual role model.
  • Dev DB was partially migrated — had the profiles student fields but not the lessons/assignments wave columns, and has no supabase_migrations.schema_migrations table. Applied the 2 missing migrations.
  • Global teardown errors on a missing public.pending_students table (harness expects it on dev) — noisy but non-blocking.
  • Smoke critical-path spec has 1 pre-existing failure ("critical console errors") — separate from this work, worth a look.
