Remote E2E runner — suite runs on the EliteDesk, not the Mac

Date: 2026-07-28 · Branch: feature/remote-e2e-runner

What was actually done

The full Playwright suite no longer needs to run on the MacBook (where it pegged the CPU for ~20 minutes and once killed the dev server mid-run). It now runs on the EliteDesk (uwh) — the machine that already hosts the StudentDevelopment Supabase stack — via two complementary entry points sharing one pipeline script:

  • CI path (primary): a self-hosted GitHub Actions runner (uwh-e2e, systemd user service github-runner-strummy) picks up the new .github/workflows/e2e.yml — triggered manually or by the e2e label on a PR. Zero billed minutes.
  • Dev-loop path: scripts/e2e-remote/run.sh rsyncs the uncommitted working tree to uwh:~/e2e/strummy and launches the same pipeline detached; status.sh monitors/fetches from the Mac.

The shared pipeline (scripts/e2e-remote/remote-runner.sh): lockfile-gated npm ci → Chromium install → production build → next start (port 3200 dev-loop / 3300 CI) → clear auth_rate_limits via local docker exec → Playwright (Desktop Chrome). A production server is used because next dev hit its memory ceiling and died under the full suite.

How to manually test it

# Step Expected
1 GitHub → repo → Settings → Actions → Runners uwh-e2e shows Idle with labels self-hosted, Linux, X64, e2e
2 Add the e2e label to any open PR (or gh workflow run e2e.yml once merged to main) An E2E run appears in the Actions tab, executing on uwh-e2e, ~8 min after warm caches
3 Open the finished run → Artifacts playwright-report artifact with the HTML report and results.json
4 PR without the label / push to a feature branch No E2E run (job skipped) — cost discipline holds
5 ./scripts/e2e-remote/run.sh from the repo root, then close the Mac's lid Run continues on uwh (runner PPID is 1); status.sh later shows progress
6 ./scripts/e2e-remote/status.sh -f after a dev-loop run test-results/remote-results.json + playwright-report-remote/ land locally
7 ssh uwh systemctl --user status github-runner-strummy active (running); survives reboot (linger enabled)

Edge cases & caveats verified

  • Port isolation: uwh's port 3000 is occupied by another app — dev-loop uses 3200, CI uses 3300; concurrency: e2e-uwh serialises CI runs.
  • Secrets: .env.local is not in the repo or GitHub — the workflow copies it from ~/.strummy-e2e/.env.local on the host (mode 600).
  • Shared DB: CI and dev-loop runs share the StudentDevelopment stack — don't run both simultaneously.
  • Baseline context: on main today ~20 specs fail because PR #549 (demo guards + final test fixes) is unmerged; the same suite passes 251/253 on that branch. Red E2E checks before #549 merges are expected, not a runner defect.
