SKL-2 — the sidebar stops lying

2026-08-15 · branch fix/skills-nav-truth · docs: docs/app-blueprint/11-skills-assessment.md

What was wrong

Sidebar.NavItem.tsx renders {t(id)} from the Nav namespace. The label field never reaches the screen — it only becomes the data-nav-item attribute. Both the teacher and student menu entries used id: 'skills', so both rendered Nav.skills = "Skills".

  • Student: the entry configured as "Practice Tools" displayed "Skills" and opened the chord-quiz hub.
  • Teacher: "Skills" sat in the Students group but opened that same chord-quiz hub — nothing to do with per-student assessment.
The E2E guard meant to catch this compared data-nav-item (the label), so it read "Practice Tools" and passed. The check was blind to exactly what it existed to protect.

The new guard was proven to fail

A test that has never failed is decoration. The id collision was reintroduced deliberately (id:'skills' + Nav.skills restored) and the new assertion caught it:

Error: nav item "skills" is labelled "Practice Tools" but renders "Skills"

Admin and teacher stayed green throughout; only the student case failed, which is the exact blast radius of the original bug. Both temporary edits were then reverted.

Design note. The first version of this assertion derived the expected text from Nav[id] — and passed against the reintroduced bug, because it agreed with the same config the DOM renders from. The invariant that actually holds is label === rendered text: the name the config declares must be the name a person reads.
