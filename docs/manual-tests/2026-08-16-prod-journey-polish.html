3. The i18n bug worth understanding

Every call site looked defensive:

t('requestSongTitle', { fallback: 'Request a Song' })

next-intl has no fallback option — the second argument is interpolation values. The text was discarded and the lookup threw MISSING_MESSAGE. Because it looked safe, 13 keys were never added to any locale. The existing locale-parity test compares en↔pl only, so a key missing from both was invisible to it.

New gate: __tests__/architecture/locale-usage.test.ts checks every t('key') in app/ and components/ against en.json, and bans the fallback option outright. Verified it fails on a reintroduced bug rather than passing vacuously:

✕ has an en.json entry for every message key used in app/ and components/
  + "Songs.requestSongActionZZZ — components/songs/requests/SongRequestButton.tsx"

5. How to verify manually

Prerequisites

npm install, then npm run dev. Sign in with the dev role accounts from CLAUDE.local.md.

#4 — sign-in badge

  1. Open /sign-in against the dev stack → a "Development" badge should still appear (it is a genuine warning).
  2. Against production, the badge must be absent. Previously it read "Remote db.strummy.online".
  3. Automated: npx jest lib/supabase/useDbConnection.test.ts — 7 cases including a lookalike-domain guard.

#7 — stage labels

  1. Go to /dashboard/lessons as a teacher, click any lesson with attached songs.
  2. In the slide-in panel, each song's stage must read "To learn" / "Started" / "Play-along" — never to_learn.
  3. Cross-check /dashboard/repertoire uses the same wording. Switch to Polish and confirm both translate.

#13 — song request dialog

  1. As a student, open /dashboard/songs with devtools open.
  2. Zero MISSING_MESSAGE errors in the console (there were ten).
  3. Click "Request a Song" — every label, placeholder and button renders real text in en and pl.
  4. Automated: npx jest __tests__/architecture/locale-usage.test.ts.

#6 / #10 — theme and nav

  1. Student dashboard: the Song-of-the-Week card uses the cream/gold palette, not blue, and is legible in dark mode.
  2. Sidebar: the item under the "Students" group reads People and opens /dashboard/users, whose heading also reads "People".

7. Still open — needs infrastructure, not code

  • Deploy production. It is 5 PRs behind; that alone resolves finding #9 and restores the student skill checklist.
  • AI chat (#1). AI_PROVIDER and OPENROUTER_ALLOW_PAID are unset in prod, so :free model ids are rewritten to the paid tier — an OpenRouter account without credits fails exactly this way. Confirm in runtime logs, then either fund the account or set OPENROUTER_ALLOW_PAID=false and pin a model that still has a free endpoint.
  • Realtime (#2). wss://db.strummy.online/realtime/v1/websocket returns 500 while rest/v1/ returns 200 — the realtime container on the prod stack needs attention. Do not run supabase stop/start without docs/runbooks/supabase-stack-restart.md.
  • Demo data (#3). All 29 lessons are in the past, titled "Lesson (imported)", all at 12:00 PM, and all 3 students are stuck at "resend invite" — so the dashboard, calendar and utilisation all read zero. Seeding a few future lessons is the single highest-value change for a recruiter's first impression.
