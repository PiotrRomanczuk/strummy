Rodzic i uczeń nie odczytają już notatek nauczyciela przez API

2026-11-16 · gałąź fix/student-private-notes · issue #1096 · migracja 20261116150000_student_private_notes.sql

Problem

RLS działa na wierszach, więc kto widzi wiersz profilu, widzi wszystkie jego kolumny. Cały wiersz ucznia dostają: sam uczeń, jego rodzic (profiles_select_parent), a wiersz nauczyciela — jego uczniowie. Pole „Cele / notatki” (profiles.notes) było więc czytelne dla każdego z nich zapytaniem do API, choć UI go nie pokazuje.

Co zostało zrobione

  • Nowa tabela student_private_notes (jeden wiersz na profil): czytają tylko admin i nauczyciel (is_admin_or_teacher(), tak jak profiles_select_staff), nikt zalogowany nie zapisuje bezpośrednio.
  • Wyzwalacz trg_profiles_move_private_notes: tekst zapisany do profiles.notes trafia do nowej tabeli, kolumna zostaje pusta, pusty tekst kasuje notatkę. Dzięki temu żaden kod zapisu się nie zmienia — formularze, /api/users, wywiad Cal.com (#1109) — i stary kod działa w chwili między migracją a wdrożeniem (expand → contract; usunięcie kolumny to osobna, późniejsza migracja).
  • Migracja przenosi istniejące notatki (dev: 1, produkcja: 1) i czyści kolumnę.
  • Odczyt: formularz edycji ucznia i GET /api/users/[id] czytają notatkę z nowej tabeli (odpowiedź API nadal ma pole notes).
  • Decyzja domyślna (issue mówiło „do decyzji”): ukryte są tylko notatki nauczyciela. Reszta wiersza zostaje dla rodzica, w tym lesson_rate — rodzic płaci za karnet i widzi cenę.

Plik zawiera update public.profiles set notes = null, więc przed produkcją czeka na zatwierdzenie w środowisku production-db (reguła 4 migracji).
