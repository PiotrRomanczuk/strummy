Sign-in, password reset, invitation and 404 in the viewer's language

2026-10-13 · branch fix/walkthrough-review-5-auth-404-i18n

What changed

  • Every auth screen (sign-in, forgot password and its "check your inbox" state, set-new-password, accept invitation, the link-error banner) and the shared password field now read from new Auth and NotFound namespaces. The invited student's first screen is no longer English.
  • Validation and sign-in errors are still produced in English by the schema and the server action; a small mapper turns the known ones (including rate-limit and lockout with their minutes) into the viewer's language. Unknown messages pass through unchanged.
  • The set-new-password page moved onto the same card layout as the rest of auth. The 404 page uses the app's serif heading and ink button instead of bold sans and brown.
  • Bug fix: the reset form said "Minimum 6 characters" while the schema requires 8 with a letter and a number. The hint and minLength now match the rule.
  • The link-error banner moved inside the translation provider in the root layout.

How to test

  1. npm run dev, browser language or the language toggle set to Polish, 390 px wide.
  2. /sign-in: everything Polish. Enter a wrong password: "Nieprawidłowy e-mail lub hasło…". Blur an invalid email: "Podaj poprawny adres e-mail".
  3. "Nie pamiętasz hasła?" → /forgot-password: Polish form; submit a real dev address and check the "Sprawdź skrzynkę." state.
  4. Open the reset link from Mailpit: Polish "Ustaw nowe hasło" card; the hint says 8 characters with a letter and a digit; a 6-character password is rejected with the Polish message.
  5. Open an expired invite link (or /accept-invitation#error=access_denied&error_code=otp_expired): Polish banner "Link z zaproszeniem wygasł…".
  6. Open /dashboard/lessons/00000000-0000-0000-0000-000000000000: Polish 404 with "Wróć do panelu".
  7. Switch to English: all texts identical to before.
