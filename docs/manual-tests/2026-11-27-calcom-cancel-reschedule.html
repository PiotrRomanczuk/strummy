Cal.com webhook: cancel and reschedule

Date: 2026-11-27 · Issue: #1080 · Branch: fix/calcom-cancel-reschedule

What changed

Before: the webhook only acted on BOOKING_CREATED. A cancelled booking left its lesson SCHEDULED; a rescheduled booking left the lesson at the old time (and its new uid was unknown). A booking without endTime got 45 minutes, and the lesson went to whichever teacher/admin row the database returned first.

EventNow
BOOKING_CREATEDUnchanged flow (student found or created, lesson created once per uid), but the teacher is CALCOM_TEACHER_PROFILE_ID and the default length is 60 min.
BOOKING_CANCELLEDThe SCHEDULED lesson with calcom_booking_id = uid becomes CANCELLED. Repeat / unknown uid / completed lesson: nothing changes (action: "unchanged").
BOOKING_RESCHEDULEDCal.com sends a new uid plus rescheduleUid (the old booking). The old booking's scheduled lesson moves to the new startTime, its length follows endTime (else 60), and its calcom_booking_id becomes the new uid. Repeat event: the new uid already has the lesson, nothing new is created (the old one is cancelled if still scheduled). Neither uid known: handled as a new booking.
other events200 { "ignored": "<event>" }, nothing touched.

Signature verification is unchanged and still fail-closed. No migration: lessons.calcom_booking_id already has a unique partial index (20260803090000).

Configuration

New env var CALCOM_TEACHER_PROFILE_ID = the profile id (uuid) of the teacher who gets Cal.com lessons, set per environment on Vercel (Production and Preview). It must have the teacher or admin role. If it is missing or wrong, bookings answer 500 and Cal.com retries them, rather than landing on a guessed teacher. Documented in lib/env.ts.

How to test manually (dev stack)

  1. In .env.local set CALCOM_WEBHOOK_SECRET to any test value and CALCOM_TEACHER_PROFILE_ID to the dev teacher's profile id. Run npm run dev.
  2. Write a body, e.g. created.json: 
    {"triggerEvent":"BOOKING_CREATED","payload":{"uid":"mt-1","startTime":"2026-12-01T16:00:00Z","attendees":[{"name":"Manual Test","email":"manual-test-1080@example.com"}]}}
    Sign and send: 
    SIG=$(openssl dgst -sha256 -hmac "$CALCOM_WEBHOOK_SECRET" -hex < created.json | awk '{print $2}')
curl -s -X POST localhost:3000/api/webhooks/calcom -H "x-cal-signature-256: $SIG" --data-binary @created.json
    Expect action: "created"; in the dashboard the lesson is with the configured teacher, 60 min.
  3. Send the same body again: same lessonId, no second lesson.
  4. Reschedule: {"triggerEvent":"BOOKING_RESCHEDULED","payload":{"uid":"mt-2","rescheduleUid":"mt-1","startTime":"2026-12-03T17:00:00Z","endTime":"2026-12-03T17:45:00Z","attendees":[...same...]}}. Expect action: "rescheduled", same lesson id, now 3 Dec 17:00, 45 min. Send again: "unchanged", still one lesson.
  5. Cancel: {"triggerEvent":"BOOKING_CANCELLED","payload":{"uid":"mt-2"}}. Expect action: "cancelled" and the lesson shows as cancelled. Send again: "unchanged".
  6. Edge cases: cancel without uid → 400 Invalid booking uid; reschedule without rescheduleUid → 400; unset CALCOM_TEACHER_PROFILE_ID and send a new booking → 500, no lesson; bad signature → 401.
  7. Clean up: delete the lesson and the shadow profile created for manual-test-1080@example.com.
