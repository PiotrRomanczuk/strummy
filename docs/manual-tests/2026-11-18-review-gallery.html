Review gallery: every main screen of test beside main

Date: 2026-11-18 · Branch: feature/review-gallery (stacked on #1104) · Scope: tests/review/, playwright.review.config.ts, scripts/review/, .github/workflows/review-gallery.yml, scripts/e2e-remote/app-server.lib.sh, tests/helpers/copy-cast.ts

What was done

  • A review pass, not a test. tests/review/screens.review.ts signs in as the same person on two builds — main on :3610 and test on :3600, same database — opens each main screen on both at the same moment, screenshots both and lets Playwright's own comparator (toMatchSnapshot against main's shot) decide "changed" and draw the diff. Nothing is asserted; a broken screen (HTTP ≥ 400, JS error, bounced to sign-in) is recorded and shown first.
  • Who and what (tests/review/review-cast.ts): public pages, the copy's busiest teacher (8 screens), that teacher's busiest student (7), a parent with a child (1). Desktop 1440 px and phone 390 px, in Polish (?lang=pl), Warsaw time. REVIEW_CAST=roles uses dev's role accounts instead.
  • The gallery (build-gallery.mjs, gallery-page.mjs): broken first, then changed with main | test | diff per device, unchanged folded away; summary.md is the short version for the review page. Every raw record is kept next to it (manifest.jsonl, results.json, run.log).
  • The run (run-review.sh, uwh): main in its own clone, rebuilt only when main, the env or Node changed; publishes to ~/strummy-review/<sha>/, keeps 20; reuses a gallery for the same test/main pair. Served LAN-only by a user unit (strummy-review-gallery.service, port 9877) — never GitHub: the repo is public and these are screenshots of a production copy.
  • Filed on the review page (post-section.sh): section screens on the open test → main PR's page in home-ops (#87), for the PR's head commit; the token is read from pr-decide's env file and never printed or put on a command line.
  • Workflow review-gallery.yml: after Deploy DB succeeds on test, when the test → main PR opens, or by hand.
  • One build implementation: the deps/build/serve code of remote-runner.sh moved to app-server.lib.sh, which both runners source.
  • Bug found by the first copy run, fixed: on the copy every address is anonymised, so @strummy.app no longer marked the demo cohort — and the demo studio, which regenerates its lessons, was "the teacher with the most recent lessons". The @copy spec from #1104 had been testing the demo studio instead of a real teacher. castFromCopy now leaves out is_development profiles.

How to test it manually

  1. One-time (owner, uwh, no sudo): 
    cp scripts/review/strummy-review-gallery.service ~/.config/systemd/user/
systemctl --user daemon-reload && systemctl --user enable --now strummy-review-gallery
curl -sI http://192.168.1.75:9877/ | head -1     # HTTP/1.0 200 OK
  2. By hand on uwh, from a checkout of test (Node 22): 
    scripts/test-stack/e2e-env.sh .env.local
E2E_DB_CONTAINER=supabase_db_StrummyTest SMTP_PORT=57325 scripts/review/run-review.sh
rm .env.local
    Expected: Gallery: http://192.168.1.75:9877/<sha>/index.html; open it from the LAN. With the same app code on both sides every screen is "bez zmian". REVIEW_MAIN_REF=<older sha> shows real changes; REVIEW_CAST=roles with dev's env runs on dev's role accounts.
  3. After merge to main: gh workflow run review-gallery.yml (or push to test: it follows Deploy DB). The run's summary page shows the same counts; with an open test → main PR at that commit and home-ops #87 deployed, its review page has a "Ekrany: test wobec main" section with the link.
  4. Edge cases: a second run for the same test/main pair prints "already exists" and only re-files the section (-f force=true renders again); no open PR → a notice, the gallery still published; home-ops not deployed → a warning, job green.

Not covered yet

  • Steps are URLs only — dialogs, forms and the invite flow are not captured (a click that exists on one side would break the other).
  • Volatile values get data-review-mask when they show up as noise; none did in run C.
  • workflow_run starts only from main's copy of the workflow; home-ops #87 must be deployed for the review-page section.
