Disabling the practice-time feature

2026-07-31 · branch feature/disable-practice-features · visibility flag only

What was actually done

Every practice-tracking read-out is now hidden behind a single switch, SHOW_PRACTICE_FEATURES in lib/config/features.ts, set to false. It follows the same shape as the existing SHOW_AI_FEATURES flag next to it.

This hides UI only. The /dashboard/practice route still resolves if you type the URL, the server actions still work, and no practice_sessions row is touched or deleted. Flipping the constant back to true restores every surface below with no other code change — that is the whole point of doing it this way rather than deleting the components.

It is off in all environments, not just production, so local dev shows exactly what users see. There is no NEXT_PUBLIC_ variable to keep in sync across Vercel environments.

How to test it manually

Setup

cd ~/Desktop/MainCV/strummy
git checkout feature/disable-practice-features
npm run dev

Sign in with the dev role accounts (email/password — Google SSO does not work against the LAN dev stack). Credentials are in CLAUDE.local.md.

1 — Student: sidebar and dashboard

  1. Sign in as the Student account, land on /dashboard.
  2. expect gone No "Practice Log" in the sidebar, and no "Progress" group heading at all. You should see only Learning and Resources.
  3. Scroll to "Songs you're working on". expect gone no 2h 5m-style minute counts on the right of each row. expect present the song title, author, and the status pill (Started / Mastered), still right-aligned and not floating mid-row.
  4. Open any song from that list. expect gone the "Practice time" row in the right-hand "Your practice" card. expect present the stage stepper.

2 — Route is hidden, not blocked (deliberate)

  1. Still as the student, type /dashboard/practice into the address bar. expect present the page still loads and logging still works. This matches how every other hidden item behaves — hiding is nav-only, so bookmarks do not hard-error.
  2. Log a session here. It saves normally. Nothing about the data path changed; the numbers simply are not surfaced anywhere else right now.

3 — Teacher: student detail and dashboard

  1. Sign in as Teacher (or Admin), go to Students → pick any student.
  2. expect gone the coloured At risk / Watch / On track pill next to the student's name, and the "· N days since practice" text under it.
  3. expect gone the "Total practice" figure in the top-right stat cluster. expect present "Songs in progress" and "Mastered".
  4. expect gone the "Practice Log" tab. Only Overview, Lessons and Repertoire remain — clicking between them should still work normally.
  5. On the Overview tab, expect gone the 14-day practice sparkbar. The Lessons card below it should move up to fill the space, not leave a gap.
  6. The action button should read "Message" in the neutral dark style — expect gone the amber "Reach out" variant, even for a student who has never practised.
  7. Go to /dashboard. expect gone the "Needs attention" card from the right-hand column. The cards below it (Week density, Utilization) should close the gap.
  8. Scroll to the "Activity" feed at the bottom. expect gone any row reading "… practiced …". expect present lesson and assignment rows — the feed should not be empty just because practice rows were removed.

4 — Parent dashboard

  1. Sign in as a parent with a linked child (or visit /dashboard?view=parent&child=<id>).
  2. expect gone the "day streak" and "this week" chips in the hero. expect present the "songs" chip, sitting alone.
  3. expect gone the "Recent practice" card. Check the layout carefully here — "Upcoming lessons" and "Billing" should sit side by side in an even two-column row, not stretched across the full width where the practice card used to be.

5 — Edge cases worth a look

  • Mobile / narrow viewport (≤ 640px): the parent dashboard grid collapses to one column anyway; confirm nothing double-stacks or leaves an empty row. Same for the student repertoire rows now that a grid column was removed.
  • Demo account tour: start the student demo tour. It should end on "My assignments" and not stall trying to point at a nav item that no longer exists.
  • Student with no repertoire: the student-detail stat cluster should show "0 / 0" cleanly with no orphaned third label.
  • Flip it back: set SHOW_PRACTICE_FEATURES = true, reload, and confirm every surface above returns. This is the check that the change is genuinely reversible rather than a deletion in disguise.

Seven suites asserted the practice surfaces and were updated. Rather than deleting those assertions, each suite now mocks the flag as a mutable property: the default matches production (off) and the practice-specific tests opt back in with featuresMock.SHOW_PRACTICE_FEATURES = true. Both states stay covered, so flipping the flag back is protected by tests rather than by hope.

One find worth noting: the student-detail tab list was originally computed at module load, which froze the flag at import time. It now reads the flag at render — otherwise a flag flip would have been silently ignored under module reuse.

E2E: tests/e2e/student/practice.spec.ts and practice-bpm.spec.ts navigate by direct URL, so they keep passing unchanged. tests/e2e/teacher/backfill-at-risk.spec.ts drives the now-unmounted "Needs attention" card and is conditionally skipped on the same flag, with its seeding logic left intact so it re-arms automatically if the flag is flipped back. E2E was not executed locally — it runs on uwh against the dev stack via the self-hosted runner.
