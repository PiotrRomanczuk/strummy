ADM-8 — /api/cohorts/analytics role check

Date: 2026-11-01 · Stack: StrummyDevelopment only · Migration: none

What was built

The route checked roles by selecting profiles.role, a column that does not exist (roles are the is_admin / is_teacher / is_student flags). PostgREST rejected the query, the profile came back empty, and the route answered 404 "Profile not found" to everyone, admins included. It now resolves roles through getUserWithRolesSSR(), like the other API routes.

Expected behaviour

Caller Before After
Signed out 401 401
Student 404 403
Teacher 404 200 + cohort JSON
Admin 404 200 + cohort JSON
Admin, missing dimension 404 400

How to verify by hand

  1. Run the app against the dev stack (npm run dev) and sign in as the dev Admin (credentials in CLAUDE.local.md).
  2. In the same browser, open 
    /api/cohorts/analytics?dimension=status&metric=lessons_completed
    Expect a JSON body with cohorts — not {"error":"Profile not found"}.
  3. Open /api/cohorts/analytics?metric=lessons_completed — expect 400 "Missing required parameters".
  4. Sign out, sign in as the dev Teacher, repeat step 2 — expect 200.
  5. Sign out, sign in as the dev Student, repeat step 2 — expect {"error":"Forbidden"} (403).
  6. Sign out entirely, repeat step 2 — expect 401.

Automated coverage

app/api/cohorts/analytics/route.test.ts — 6 cases: 401, 404 (no profile), 403 student, 200 admin, 200 teacher, 400 parameter validation. No E2E: this is not a critical user flow and the route has no UI consumer yet (chart slots on the analytics page are still placeholders).
