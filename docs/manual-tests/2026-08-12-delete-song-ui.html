Delete song — manual test report

What was actually done

A teacher/admin previously had no way to delete a song from the UI, even though the backend (DELETE /api/song, the soft_delete_song_with_cascade RPC) worked correctly. Root cause: a 2026-06-10 cleanup commit (521451cb, "delete v1 song-detail + v2 SongDetail wrappers") deleted components/songs/details/Actions.tsx (the old Edit/Delete buttons component) while consolidating onto the new SongDetail.tsx/SongHero.tsx. Edit got carried forward into SongHero.EditLink.tsx; Delete never did. The gap went unnoticed because the E2E test for song deletion called page.request.delete('/api/song?id=...') directly instead of clicking anything — it proved the API worked, not that a user could delete a song through the app.

This change:

  • Adds a deleteSong server action (app/actions/songs.ts) — reuses the same soft_delete_song_with_cascade RPC as the existing (unused) bulk-delete action, gated to teacher/admin, test-account guarded.
  • Adds SongHero.DeleteButton.tsx — a "Delete song" button next to the existing "Edit song" link and "Set as Song of the Week", opening an AlertDialog confirmation (title + song-specific description), then redirecting to /dashboard/songs on success.
  • Wires it into SongHero.tsx behind the same canEdit prop (isAdmin || isTeacher) already gating the Edit link — students see neither.
  • Adds new English/Polish i18n strings (deleteSongLink, deleteSongConfirmTitle, deleteSongConfirmDescription).
  • Rewrites tests/e2e/teacher/songs-crud.spec.ts's delete step to click through the real UI (list row → slide-in panel → "Open full page" → "Delete song" → confirm in the dialog) instead of calling the API directly.
  • Adds unit coverage: SongHero.test.tsx (button gating by role) and app/actions/__tests__/songs.test.ts (deleteSong action: unauthorized, unauthenticated, success, RPC transport error, RPC-reported failure).
  • Corrects the stale components/songs/README.md line that still pointed at the deleted Actions.tsx.

How to manually test it

  1. Sign in as a teacher or admin (dev quick-login buttons on /sign-in work).
  2. Go to Songs, click any row to open the slide-in preview panel.
  3. Click "Open full page" to land on /dashboard/songs/[id].
  4. Confirm a red "Delete song" button appears next to "Edit song" and "Set as Song of the Week".
  5. Click it → a confirmation dialog appears naming the song and warning the action is permanent and cascades (unassigns from lessons/repertoire).
  6. Cancel — dialog closes, song is untouched.
  7. Click Delete again → confirm → button shows a spinner while pending → redirects to /dashboard/songs → the song is gone from the list.
  8. Edge case — role gating: sign in as a student and open the same song's full page directly by URL. Neither "Edit song" nor "Delete song" should render.
