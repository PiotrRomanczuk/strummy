What was done

  • Workflow e2e-test.yml: nightly 02:47 UTC (after the dev nightly matrix) and on dispatch. Checks out test, waits for a running refresh, writes the StrummyTest env, runs every spec on Desktop Chrome without fail-fast, and posts the commit status E2E on StrummyTest (pending → success / failure / error) on the tested test commit — the head of a test → main PR. Report on the summary page and as an artifact.
  • Accounts on the copy: after the anonymisation, refresh.sh creates dev's four role logins (admin/teacher/student/parent@dev.local, the same roles, names and parent link as on dev) with the shared test password — not the dev passwords, which are public in this repo — and rebuilds the demo studio with emit-demo-sql.ts, the SQL production's demo was built with. The specs run unchanged.
  • e2e-env.sh: the run's .env.local = the dev E2E env minus every Supabase/Postgres line (that file also holds production's keys), plus all Supabase names pointing at StrummyTest. Refuses to write if a production address is left.
  • @copy spec (StrummyTest only): signs in as the copy's busiest teacher, that teacher's busiest student and a parent with a linked child, and opens their main pages — status < 400, no error boundary, no uncaught exception, no bounce to sign-in/onboarding.
  • Cleanup guard: the global teardown never deletes @test.strummy.invalid accounts.
  • refresh.sh waits until Kong is healthy before it reports "API open" and releases the lock.
