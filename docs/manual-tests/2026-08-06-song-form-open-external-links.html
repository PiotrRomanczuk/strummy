Open-link affordance on song form URL fields

Date: 2026-08-06  ·  Branch: feature/song-form-open-external-links  ·  Surface: /dashboard/songs/[id]/edit and /dashboard/songs/new

What was built

The four external-reference fields in section III · Materials of the song form — YouTube URL, Spotify link, Ultimate Guitar, TikTok short — now render a small gold OPEN ↗ link in the field's label row whenever the field already holds a usable URL. Clicking it opens that URL in a new tab, so you can jump straight to the Ultimate Guitar tab (or the Spotify track, etc.) while filling in the rest of the song's data, without selecting and copying the text out of the input.

The affordance is reactive: it appears as soon as the field contains a valid absolute http(s) URL, and disappears again if you clear or break the value. It is deliberately not shown for a half-typed URL, a relative path, or a non-http scheme such as javascript: — an anchor is only ever given an href that has been parsed and scheme-checked by openableHref(). This is the same failure class as the empty-href CTA bug fixed in #663.

Because the affordance lives on the shared Field component, both the create form and the edit form get it from the one change. Nothing about saving, validation, or the submitted form payload changed.

Setup

  2. Open http://localhost:3000/dashboard/songs and sign in via Dev Quick Login → Admin
  3. Click any song, then Edit, and scroll to section III · Materials / Linki zewnętrzne

Cases

# Do this Expect
1 Look at the four URL fields while they are all empty No "OPEN" link anywhere — only the "OPTIONAL" badge on each label
2 Type https://tabs.ultimate-guitar.com/tab/oasis/wonderwall-27596 into Ultimate Guitar A gold OPEN ↗ appears in that field's label row only. The other three stay bare.
3 Click OPEN ↗ Ultimate Guitar opens in a new tab; the edit form keeps all its unsaved state in the original tab
4 Delete the last few characters so the value reads tabs.ultimate-gui The OPEN link disappears while the value is not a valid URL, and returns when it is again
5 Paste javascript:alert(1) into TikTok short No OPEN link is rendered — the scheme is rejected, so no unsafe href reaches the DOM
6 Open a song that already has a saved Spotify or YouTube link, without typing anything The OPEN link is present from first paint on each populated field
7 Repeat case 2 on /dashboard/songs/new Identical behaviour — the create form shares the same Field component
8 Switch the UI language to Polish The label reads OTWÓRZ ↗
9 Save a song after using the OPEN link Save behaves exactly as before — the affordance is display-only and submits nothing

Edge cases worth a look

  • A URL with query params or a fragment (?tab=1#chorus) — link should carry them through intact
  • A pasted value with leading/trailing whitespace — trimmed, link still works
  • Narrow viewport (≤480px) — the label row wraps without pushing the "OPTIONAL" badge off-screen
  • Dark mode — the gold link uses var(--gold-2), which has a dark-theme value in design-tokens.css
