What was actually done

A full E2E run (251✓/2✘) led to a deep diagnosis. The two failing specs turned out to sit on top of one real app bug and two test-infrastructure landmines. One landmine had already deleted the shared teacher@dev.local profile from the dev database (restored by hand from the audit log). This change fixes all of it:

File Change
tests/helpers/cleanup.ts isProtectedAccount() guard: profiles with @dev.local / @strummy.app emails (plus the owner's email) can never be deleted by cleanupTestUsers(), which matches on full_name /^E2E/ and previously deleted the real teacher after a crashed run left it renamed.
tests/e2e/teacher/settings-persist.spec.ts Rename prefix changed to Settings Persist <ts> (cleanup can't match it); afterEach restores the constant canonical name Sarah Mitchell instead of a read-back value (kills the poisoned-baseline cascade); the save is verified against the database with a retry-click loop instead of waiting on the "✓ Saved" badge (the badge intermittently never renders due to a client-side React action-transition wedge — the save itself persists).
tests/e2e/notifications/inbox.spec.ts "Mark all read" asserts persistence via DB poll with retry-click, then reloads and asserts the button is gone — same wedge-proofing.
lib/auth/loadAuthedProfile.ts .single() → .maybeSingle(); query errors now throw instead of collapsing into "no profile". Previously a transient error bounced a fully-authenticated user to /onboarding (pages) or returned 403 "Profile not found" (API). Now pages hit the error boundary and APIs 500 — honest and retryable. null is reserved for "account genuinely has no profile row".
app/actions/profile-settings.ts Update now uses .select('id') and returns an error when 0 rows matched — no more "✓ Saved" for writes that never happened (also surfaces the post-S2 id/user_id mismatch loudly instead of silently).

How to manually test

1. Settings save still works (happy path)

npm run dev   # or use the preview deploy
  1. Sign in as teacher@dev.local / test123_teacher.
  2. Go to Dashboard → Settings, change Display name, click Save changes.
  3. Expect the ✓ Saved badge; reload — the new name survives.

2. Zero-row save now fails loudly

  1. In the dev DB, temporarily rename the profile's id linkage or use a post-S2 account whose profiles.id ≠ user_id.
  2. Save from Settings → expect "Could not save. Try again." instead of a false ✓ Saved. Server log shows [profile-settings] update matched no rows.

3. Cleanup can no longer delete shared accounts

# rename the teacher to a name that matches the cleanup pattern, then run teardown
docker exec supabase_db_StudentDevelopment psql -U postgres -d postgres \
  -c "UPDATE profiles SET full_name='E2E Settings 999' WHERE email='teacher@dev.local';"
npx playwright test settings-persist --config=playwright.remote.config.ts  # teardown runs after
docker exec supabase_db_StudentDevelopment psql -U postgres -d postgres \
  -c "SELECT full_name FROM profiles WHERE email='teacher@dev.local';"   # row MUST still exist

4. E2E stability proof (the former 40–50% flake)

./scripts/e2e-remote/run.sh inbox.spec.ts settings-persist.spec.ts
# then loop settings-persist several times on uwh — all iterations must pass
