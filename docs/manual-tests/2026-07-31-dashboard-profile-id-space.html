Manual test report · production bug · found by using the app

The dashboard was asking for the wrong id, so it showed nothing at all

Date: 2026-07-31  ·  Branch: fix/dashboard-profile-id-space  ·  Files: app/dashboard/page.tsx, components/dashboard/parent/ParentView.tsx

What was wrong

Signing in as a teacher with 50 completed lessons and four students produced a dashboard that said there was nothing there:

  • “No lessons on your books today.”
  • “Everyone’s on track this week.”
  • “No active students yet.”
  • Utilization 0% · 0.0h / 40h, and a week-density strip of all zeros.

Nothing errored and nothing was logged. The page rendered perfectly — it just rendered the empty state, because every query it ran returned zero rows.

Why

Since the identity-model rebuild, profiles.id is an independently minted primary key and profiles.user_id is the link to the auth account. They are different values. Every domain foreign key — lessons.teacher_id, lessons.student_id, assignments.teacher_id, profiles.parent_id — points at profiles.id.

The dashboard resolved the signed-in user and passed the auth id to all of them. The file even documents the distinction correctly one function higher up: 

// userId here is the auth id (auth.uid()), never profiles.id
.eq('user_id', userId)          // loadProfileName — correct

getTeacherRoster(userId)        // filters lessons.teacher_id — profile-id space

Comparing a profile-id column to an auth id is not a type error and not a runtime error. It is a perfectly valid comparison that simply never matches, so the failure mode is silence. That is what made this survive: the name at the top of the page (“Good morning, …”) loaded fine, because that one query correctly matched on user_id.

Every affected query

View Query Filters on Visible effect
Teacher getTeacherDayLessons teacher_id Today’s schedule always empty
getTeacherRoster teacher_id “No active students yet”
getAtRiskStudents teacher_id “Everyone’s on track”
getOverdueAssignments teacher_id Follow-up list always empty
getWeekDensity teacher_id Week strip all zeros, 0% utilization
getStudioActivity teacher_id Recent activity feed empty
Student getStudentNextLesson student_id “No upcoming lesson”
getStudentTopSongs student_id Repertoire empty on the dashboard
getStudentOpenAssignments student_id Assignments never shown
Parent getParentChildren parent_id No linked children
The student view matters most here. It means a student who claims their invite lands on a dashboard showing no lessons and no songs, however complete their records are. That was the one part of the invite flow still unverified, and this is the answer to it.

The fix

getUserWithRolesSSR() already returns profileId alongside user — it was simply not being used here. The page now passes both, and each call gets the id space it actually queries: loadProfileName keeps the auth id, everything else gets the profile id. 

const { user, profileId, isAdmin, ... } = await getUserWithRolesSSR();

<TeacherView userId={user.id} profileId={profileId} email={...} />

getUserWithRolesSSR deliberately defaults profileId to the empty string rather than user.id, precisely so a mistake here yields zero rows instead of another account’s rows. That default is doing its job; it just needed to be wired through.

How to verify by hand

Staging shares the production database, so the real 50 lessons are visible there. No setup or seeding needed.

  1. Sign in at strummy.online as the production test teacher (p.romanczuk+testteacher@gmail.com — password in CLAUDE.local.md).
  2. Land on /dashboard. Expected: the “Roster” card lists Kuba Spiridono, Michal Wojcik, Ola Wojciechowska and Quentin — not “No active students yet”.
  3. Expected: “Week density” and “Utilization” reflect real lessons rather than a flat zero. (All 50 imported lessons sit in the past, so today’s schedule saying “nothing booked” is correct and not a regression.)
  4. Cross-check the number against /dashboard/lessons, which should read “50 lessons · grouped by date”.
  5. Student side: sign in as a claimed student account and confirm the dashboard shows their next lesson, songs and assignments rather than three empty cards.

Edge cases worth a look

  • An account with no profile row. profileId is '', so every card shows its empty state — the same as before, and still no crash and no cross-account leakage.
  • The greeting still resolves. “Good morning, …” comes from the one query that matches on user_id; it should be unchanged.
  • Admin view takes no user id and is unaffected.
