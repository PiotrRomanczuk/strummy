Identity id-space fixes + audit remediation

2026-08-01 · branch fix/identity-id-space-regression · follows docs/analysis/2026-08-01-teacher-student-playwright-audit.md

A production Playwright audit found that most of the teacher-facing write surface was dead. This is the fix, plus the smaller defects the same audit turned up.

What was wrong

Since the identity-model rebuild, profiles.id and auth.users.id are different values. Domain columns — lessons.teacher_id, assignments.student_id, teacher_students.teacher_id and the rest — all hold profile ids. Roughly two dozen call sites were still passing the auth id into them.

A filter with the wrong id returns zero rows rather than an error, so nothing failed loudly. Every affected screen simply looked empty or permanently unauthorised, which reads exactly like "no data yet".

The eight 403 routes were a second trap. They authorised against the user_overview view, which selects profiles.id AS user_id and never exposes the auth linkage at all — so no auth id could ever match. They now read profiles directly.

How to test it — teacher

Sign in as the teacher test account on production (credentials in CLAUDE.local.md).

1 · Create an assignment — the headline fix Go to /dashboard/assignments/new. The Student dropdown must list your students, not just "Select a student…". Pick one, give it a title, save.
Before: the dropdown had no students and the form could not be submitted.
2 · See it in the list /dashboard/assignments should show the new assignment and a non-zero count on the status chips.
Before: "All 0" regardless of what existed.
3 · Act on it Open the assignment. You should see the Edit link and the full set of status transitions including cancel. Open /dashboard/assignments/<id>/edit directly — you should stay there.
Before: no Edit link, and the edit URL bounced you back to the detail page.
4 · Write a lesson note Open any lesson from /dashboard/lessons. An Edit affordance must be present. Follow it, add notes, save, and confirm they render on the detail page.
Before: the page said "Add them from the edit view" and offered no link to it.
5 · Schedule a lesson /dashboard/lessons/new — the Student dropdown lists real students (the "+ New student by email…" escape hatch stays, but should no longer be the only option).
6 · AI Assistant /dashboard/ai — pick a student in either tool; the Analyze / Generate button must enable.
The AI chat at /dashboard/ai/chat is a separate, still-open problem — see "Not fixed here" below.
7 · Templates Save an assignment as a template, then confirm it appears under /dashboard/assignments/templates and can be started from the create form.

How to test it — student

8 · Homework arrives Sign in as the student test account. The assignment you created in step 1 should be listed at /dashboard/assignments, and you should be able to change its status and tick checklist items.
9 · New nav entries The sidebar's Resources group now offers Fretboard and Practice Tools. Both already worked but were reachable only by typing the URL. Open the chord quiz and answer a question — it should say Correct!/Incorrect and advance.
10 · Greeting and mobile layout On a 390 px-wide viewport, the dashboard must not scroll sideways.
Before: an account with no profile name was greeted "Good morning, P.romanczuk+testteacher." — the unbroken 38-character string forced the page to 486 px. Now: a name-like fragment ("Romanczuk"), or "there" when the address yields nothing, and the heading wraps.

Things that should be silent

  • Open DevTools console on /dashboard/ai/chat, /dashboard/skills/chord-quiz and a lesson edit page. No React #418 hydration errors. The chat welcome bubble no longer prints a clock time (it was server-rendered in one time zone and hydrated in another); the quiz builds its questions after mount instead of during render.
  • /api/stats/weekly, /api/students/pipeline and /api/students/needs-attention now return 404. All three had zero callers and authenticated without checking a role. /api/students/health is untouched and still backs the Health page.

Landing page

  • Metrics re-measured and rounded down: 150+ releases (was "110+", actual 157), 390+ songs (was "400+", actual 393 — the library has never held 400), 3,800+ tests (was "3,200+", actual 3,845).
  • The hardcoded "v0.113 · Jul 2026" badge is gone. It had rotted 50 releases behind and there is no reliable build-time source for the real version, so the "See what's shipped" link to the releases page carries that job instead.
  • The footer's Beta notice link pointed at #. It now opens /beta — a new page covering what beta means, what is stored and where, students under 18, and how to get data exported or deleted. Please read it and correct anything inaccurate before this ships; it makes commitments on your behalf.

Guard against a repeat

__tests__/architecture/profile-id-space.test.ts already ratcheted this bug class, but only where the auth id was used inline in a filter. Every site in this fix was invisible to it, because the offending .eq() sat one call deeper.

It now also derives the set of functions whose first parameter feeds a profile-id column (33 of them today, including the two that caused this outage) and flags any caller handing one user.id. It also catches the JSX prop form, teacherId={user.id}, which shipped in both template pages.

Verified the check actually fires: re-introducing getStudentOptions(user.id, …) on the AI page fails the suite. Test fixtures across five files now give the auth id and the profile id different values, so writing the wrong one can no longer pass.

Not fixed here — still open

  • AI chat is dead in production — it answers "the configured model is unavailable". A provider/model configuration problem, not an id problem, and it needs the OpenRouter side checked. This is the third time this surface has broken this way; it deserves a synthetic check that sends a real prompt.
  • Roughly 40 more id-space sites across notifications, the calendar sync writers, chord SRS, song requests, song-of-the-week, theory, exports and the dashboard stats API. They are catalogued with file:line in the analysis document. Several are already recorded in the ratchet's baseline as known-deferred work.
  • teacher_students is derived from lessons, so a student is only pickable once they already have a lesson with you. A newly invited student still cannot be given their first assignment. This needs a product decision — derive from lessons, or make the teacher-student link a real relation.
  • Song library hygiene — about ten duplicate titles and a few test rows (Control Song 1774261460408, UG tab 1863704, Alex G Runnner).
