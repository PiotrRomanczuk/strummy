Polish i18n — infrastructure + landing page

Created 2026-07-30 · Branch feature/polish-i18n-localization

What was built

Strummy now supports Polish as a second language, selectable via a language toggle — no /pl URL prefix, cookie-based instead (see the plan's rationale: the dashboard is 100% behind auth, so URL-based SEO doesn't apply there).

  • next-intl installed and wired into the App Router ( i18n/request.ts, next.config.ts).
  • Locale resolution happens in proxy.ts on every request: signed-in user's profiles.locale > existing NEXT_LOCALE cookie > browser's Accept-Language header > English default. The resolved value is always written back as the NEXT_LOCALE cookie.
  • profiles.locale column added (migration 20260730130000_profiles_locale.sql), so a signed-in teacher's language choice follows them across devices/browsers.
  • Language switcher (components/layout/LanguageToggle.tsx) — in the landing page nav (logged out) and the dashboard sidebar footer (logged in).
  • Landing page fully translated — all 19 files under components/landing/, ~150 strings.
  • Zod validation messages — piloted a translation-key convention (Validation.* namespace) on 3 schemas (UserSchema, SongSchema, ProfileSchema) as the pattern for Phase 3.
  • Test infrastructure — a fixed-English NextIntlClientProvider test wrapper, plus a resolver for async Server Components (next-intl's getTranslations requires them) so existing Jest/RTL suites keep passing unchanged.
Not in this pass: the ~20 dashboard domains (lessons, songs, students, settings, admin, etc. — ~2,000–3,000 strings across 427 files) are tracked as follow-up batches (A/B/C) in the Obsidian vault, not part of this PR.

How to manually test

Setup

cd strummy && npm run dev

Open http://localhost:3000/ in a browser.

1. Browser-language auto-detection

  • If your OS/browser language is Polish, the landing page should render in Polish on first visit with no prior cookie (proxy reads Accept-Language).
  • Otherwise it renders in English by default — also expected.

2. Manual language switch (logged out)

  1. Click the language icon in the top nav (next to "Sign in").
  2. Pick the other language from the dropdown.
  3. The whole page re-renders in the new language — headline, nav, feature sections, footer, etc. verified
  4. Reload the page (hard refresh) — the choice persists (cookie-backed). verified

3. Manual language switch (logged in)

  1. Sign in with a dev account (see CLAUDE.local.md for credentials).
  2. Open the language toggle in the dashboard sidebar footer (next to the theme toggle).
  3. Switch language — dashboard chrome that has been translated should update.
  4. Sign out and back in on a different browser/profile — the choice should follow the account (persisted to profiles.locale, not just the cookie).

4. Edge cases worth checking

  • Incognito/private window with no cookie yet — should fall back cleanly to English or Polish per Accept-Language, no flash of missing translations.
  • Switching languages rapidly (click through both options a few times) — no stale/mixed-language render.
  • Screenshots embedded in the Features section (/screenshots/*.png) are static images — their in-image UI text stays English regardless of locale, which is expected (documented as out of scope; image content isn't extractable via next-intl).
