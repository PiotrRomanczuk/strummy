What was done

PartChange
Migration 20261126100000_student_song_progress.sql Table student_song_progress, an append-only history: student, song, part_label (form letter from song_segments.parts; NULL = whole song), tempo_percent 1..200, lesson, marker, time. Classified additive. RLS: select for admin, the teacher of the student (a lesson together), the student and a parent; insert for admin or a teacher who may_teach_student, with marked_by = the caller; delete for the marker or admin; no update policy.
Status rule lib/services/song-part-progress.helpers.ts Latest mark per part wins. No marks: not_started; any mark: started; mastered when every part of the song is at 100% or more (or, for a song without parts, the latest whole-song mark is).
Query and action getSongPartProgress(studentId, songId) and server action markSongPartTempo, validated by SongPartTempoInputSchema.

How to check

npx jest lib/services/song-part-progress app/actions/__tests__/song-part-progress
npm run test:rls -- student-song-progress   # after the migration is on dev
  • Rule: a later lower tempo un-masters a part; repeats of a part share one label; unknown labels are ignored.
  • RLS: teacher of the student writes and reads; another teacher neither; the student and a parent read; nobody updates; only the marker deletes.
  • The migration was run inside a rolled-back transaction on the dev database (nothing applied there).
