skill_level single source + typed schedule columns

Date: 2026-07-27 · Scope: findings 5 + 6 of docs/analysis/2026-07-27-migrations-architecture-review.md + onboarding profile-id fix

What was actually done

  • skill_level now lives in exactly one place: profiles.skill_level. Previously the onboarding wizard saved it into user_preferences.skill_level while the "Add student" intake form saved it into profiles.skill_level — two values that could disagree. Migration 20260727120000 copies any onboarding-only values onto the profile, then drops the duplicate column. The onboarding action now writes profiles.skill_level, and the teacher's student-detail "About" line reads it from there (goals and learning style still come from user_preferences).
  • The recurring lesson slot is now typed data, not free text. profiles.lesson_day ('Thu') and lesson_time ('4:00 PM') are replaced by lesson_day_of_week (smallint, ISO 8601: 1 = Monday … 7 = Sunday, CHECK-enforced) and lesson_time_local (Postgres time). Migration 20260727123000 parses existing text values (case-insensitively; unparseable junk becomes NULL, never an error) and drops the old columns. The Schedule section of the student forms now uses a weekday dropdown (full day names) and a native time picker instead of a free-text "4:00 PM" field.
  • Onboarding identity bug fixed. completeOnboarding used the auth uid (auth.getUser()) for both the profiles update (.eq('id', user.id)) and the user_preferences.user_id upsert — both columns are PROFILE-id space, which only worked because existing profiles coincidentally have id == user_id. The action now resolves the profile id once (profiles.user_id = auth uid → profiles.id) and uses it for both writes.

4 · Edge cases

  • API rejects lessonDayOfWeek: 0 / 8 and lessonTimeLocal: '4:00 PM' (Zod: 1–7, HH:MM) — try via PUT /api/users/<id>.
  • DB CHECK rejects out-of-range days even for direct SQL (update profiles set lesson_day_of_week = 9 … → constraint violation, verified on dev).
  • Both migrations are idempotent — re-applying each file is a no-op (verified on dev).
