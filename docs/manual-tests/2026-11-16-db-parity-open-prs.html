Kontrole bazy nie padają już przez cudze migracje na dev

2026-11-16 · gałąź fix/db-parity-open-pr-migrations · issue #1100 · tylko CI i skrypty

Co zostało zrobione

  • Nowy krok w obu zadaniach (db-parity, migrations-replay): fetch-open-pr-migrations.sh pobiera migracje dodane przez inne otwarte PR-y — tylko z gałęzi tego repo, nie z forków (SQL jest wykonywany jako postgres w kontenerze dev).
  • open-pr-migrations.lib.sh: każdy taki PR jest próbnie nakładany na kopię bazy porównawczej i zostaje tylko wtedy, gdy zmniejsza różnicę względem dev. Migracja, której nikt nie nałożył na dev, niczego nie zmienia; obiekt, którego nie tłumaczy żaden otwarty PR, dalej wywraca kontrolę.
  • db-parity buduje „produkcja + migracje oczekujące” także wtedy, gdy dany PR nie ma własnych migracji, a inne otwarte PR-y mają. Produkcja nadal jest tylko czytana.
  • DB types drift (wymagany) miał ten sam problem: typy generował z dev. Teraz generuje je z bazy tymczasowej zbudowanej z migracji samej gałęzi (REPLAY_BUILD_ONLY=1 w check-migrations-replay.sh, TYPES_DB_NAME w gen-types.sh), a potem ją usuwa.
  • Baza tymczasowa dostaje rozszerzenia trzymane na stacku w schemacie extensions (pgcrypto, uuid-ossp…) zanim ruszą migracje — inaczej create extension z migracji wkładał je do public i ich funkcje pojawiały się w wygenerowanych typach.

Co sprawdziłem (uwh, baza dev, bez produkcji)

check-migrations-replay.sh z kodem main i migracjami otwartych PR-ów #1005, #1027, #1078, #1106 pobranymi skryptem:

DRIFT … TABLE public.song_analysis_sources, TRIGGER trg_lessons_sync_credit_entry …
== z migracjami otwartych PR-ów
  + open PR #1005's migrations are already in dev (90 → 66 diff lines)
  + open PR #1027's migrations are already in dev (66 → 0 diff lines)
OK: replaying supabase/migrations reproduces the development schema exactly.

#1078 i #1106 (migracji nie ma na dev) zostały pominięte. Bazy tymczasowe usunięte, katalog roboczy na uwh usunięty.

Typy (uwh, po poprawce rozszerzeń):

== typy z dev (stara kontrola)
DRIFT: database.types.ts does not match the live schema.
>       song_analysis_sources: {          ← tabela z otwartego #1005
== typy z migracji gałęzi (nowa kontrola)
Replaying 80 migrations into strummy_types_shadow_check …
database.types.ts is up to date with the schema.

Pierwsza próba bez poprawki rozszerzeń dawała różnicę w funkcjach pgp_armor_headers itd. (pgcrypto w public) — stąd zmiana w schema-dump.lib.sh. Po niej migrations-replay z otwartymi PR-ami nadal przechodzi (90 → 66 → 0).

check-db-parity.sh nie był uruchamiany ręcznie, bo czyta produkcję — sprawdzi go CI tego PR-a (zadanie uruchamia skrypty z gałęzi PR-a). YAML workflow zwalidowany; gh na hoście runnera obsługuje użyte pola.
