E2E suite: safe to run against production

2026-10-11 · branch fix/e2e-prod-safety · background: docs/audits/2026-10-11-e2e-prod-safety-audit.md

What was done

  • One production guard (tests/helpers/prod-guard.ts). It now sits where service-role clients are built (seed-ids.adminClient(), cleanup, the RLS isolation spec), not only on global teardown. 11 copy-pasted unguarded adminClient() functions in specs were replaced by the shared one.
  • Guard checks the URL that is actually written to. Guard and cleanup used to resolve different env vars, so REMOTE_URL=prod + URL=dev passed the guard and still deleted on prod.
  • Missing prod hosts added: prod Kong 192.168.1.75:54321 and the legacy strummy-db.marszal-arts.online. Owner plus-aliases (p.romanczuk+…@gmail.com, the prod QA accounts) are now protected from pattern deletes.
  • Preflight signs in against the target (E2E_TARGET_SUPABASE_*), not .env.local's dev stack. It refuses a production app paired with a dev auth endpoint, and rejects @dev.local defaults without a network call. Admin is optional, checked only when configured.
  • playwright.prod.config.ts: per-project grep: @prod-safe, which CLI --grep can narrow but not widen. testIgnore covers the specs that mutate data through the UI. Any service-role client is refused for the whole deployed run. Two projects instead of ten, and a separate session cache (tests/.auth/deployed/). Accounts come from the gitignored .env.e2e-prod.local.
  • 40 tests tagged @prod-safe per project in 13 files: smoke, role login (teacher/student), list pages, access control, fretboard, avatar validation, stub routes, mobile song list.
  • Bug fixed: rls-data-isolation deleted users by u.authId, a field that does not exist, so it leaked 3 auth users per run. It now deletes by u.id and pages through every user.
  • npm run test:pw:prod plus a "Running Against Production" section in tests/README.md.
