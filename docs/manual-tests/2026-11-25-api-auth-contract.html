API auth contract

2026-11-25 · API only, no UI change · tests run with no mocks: real HTTP against the app on the dev stack

What was done

  • tests/e2e/cross-role/api-anonymous-access.spec.ts reads every app/api/**/route.ts from disk (132 routes, 182 method endpoints) and calls each one as a visitor with no cookie, token, API key, cron secret or webhook signature. Every answer must be 401 or 403, except 7 endpoints that are public on purpose, listed with their reason and the statuses they may return. A new route without authentication fails this spec.
  • tests/e2e/cross-role/api-auth-roles.spec.ts pins withApiAuth with real accounts, real JWTs and real API keys: 401 for missing, malformed or forged credentials; 403 for an account without a profile; role-only routes let in exactly their role; an API key stops working when revoked or expired; only staff add songs through the external API.
  • Fixes the specs found:

How to test manually

  1. Start the app on the dev stack and run the specs: 
    npm run dev
npx playwright test tests/e2e/cross-role/api-anonymous-access.spec.ts tests/e2e/cross-role/api-auth-roles.spec.ts --project="Desktop Chrome" --workers=1
    Expect 7 passed. The roles spec creates its own accounts (api-auth-*@example.test) and deletes them.
  2. By hand, without signing in: 
    curl -s -o /dev/null -w "%{http_code}\n" -X DELETE "http://localhost:3000/api/spotify/sync/stream?syncId=x"
    Expect 401.
  3. With an API key whose expires_at is in the past (set it in Studio on dev): 
    curl -s -H "Authorization: Bearer gcrm_…" http://localhost:3000/api/song
    Expect 401 {"error":"API key expired"}; clear expires_at and expect 200.
  4. As admin in the app: start a Spotify sync from the songs admin page and cancel it — cancelling still works.
