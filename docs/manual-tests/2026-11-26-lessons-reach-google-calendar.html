Lessons reach Google Calendar

Date: 2026-11-26 · Branch: fix/calendar-push-profile-id (PR #1202) · Checked on: Mac, unit tests only — no browser session, because the dev stack has no teacher with a connected Google account.

What was done

Before After
The push looked up the Google integration by lessons.teacher_id, a profile id. For every account created since S2 that id differs from the auth id the integration is stored under, so no lesson ever reached the calendar. The teacher's profile id is turned into the auth id first (connectedGoogleUser).
Create and update sent no lesson length, so Google made every event 60 minutes. With the calendar → lessons sync (#1201) that 60 would come back as a resize of a 45-minute lesson. Create sends the lesson's length. A move or a new length sends the saved start and length together. A length change made in Strummy alone now reaches Google too (it used to be skipped).
Two overlapping test files; the old one stopped reaching the Google calls after the fix. One colocated test file, 100% of the module covered (the threshold in jest.config.ts).

How to test it manually

  1. Sign in as a teacher whose account was created after S2 and connect Google Calendar in Settings.
  2. Create a 45-minute lesson. Expected: the event appears in Google Calendar, 45 minutes long.
  3. Move the lesson by an hour in Strummy. Expected: the event moves and stays 45 minutes.
  4. Change only the length to 30 minutes. Expected: the event's end moves; its start does not.
  5. Change only the title. Expected: the event is renamed; its time does not change.
  6. Delete the lesson. Expected: the event disappears.
  7. Disconnect Google and edit a lesson. Expected: the edit saves, nothing is sent, no error is shown.
