Chord shape for F# (#1240)

Date: 2026-11-27 · Branch: fix/chord-shape-f-sharp · Scope: song page chord voicings, song card shapes

What was done

  • One chord library. The song page ("Chords in <song>") drew from its own table in SongPrimitives.tsx; the song card drew from CHORD_VOICINGS (lib/music-theory/chord-voicings.ts). Neither had F#. The song-page table is gone; both places (plus the backing track, the student chord chart) now ask one function, voicingForChord() in lib/music-theory/chord-voicing-lookup.ts.
  • New shapes (lib/music-theory/chord-voicings-songs.ts): F# 244322 (2nd-fret E-shape barre), C#, Eb, Ab, Bb; Cm, Ebm, Fm, Gm, Bbm; F7, F#7, Bb7, Bm7, F#m7; the open shapes only the song page had (Gmaj7, Cadd9, Asus4, Dsus2, Esus4, D/F#, G/B, C/G); a power chord on every root.
  • Name handling: enharmonics (Gb → F#, A# → Bb, Abm → G#m, D#m → Ebm), the ♯/♭ signs, Polish names (fis, h, as, lowercase = minor), CM7/Maj7 → maj7, bare sus → sus4, slash chords (written shape if there is one, else without the bass), and extensions fold into the triad the student plays (Em9 → Em, A7sus4 → A), as the chord map already does. Half-diminished / flat-five chords do not fold.
  • Test against real data: the 165 distinct chord symbols the songs on the dev stack use (songs.chords + song_analyses.chords, read-only, symbols only) are a fixture; the test fails if any has no shape, except an explicit allow-list (D#m7b5, Fmaj7b5).
  • The song card shows the written name above a folded shape (e.g. "Em7/D" over the Em7 diagram).
