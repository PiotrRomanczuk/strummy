Spotify callback: refresh token no longer in the URL

2026-11-15 · sprint task code-strummy-spotify-callback · no screenshots: the OAuth round trip needs a real Spotify login and was not run locally; evidence is the Jest tests below.

What was done

After Spotify login, /api/spotify/callback used to redirect to /dashboard/admin/spotify-connect?success=true&refresh_token=…. The token therefore ended up in browser history, Vercel logs and the Referer header. The route also wrote it to the application log in plain text.

  • The redirect is now just ?success=true.
  • The token travels in a cookie spotify_refresh_token_once: httpOnly, SameSite=Lax, Max-Age=300, Path=/dashboard/admin/spotify-connect, Secure in production.
  • The admin page calls the Server Action consumeSpotifyRefreshToken() once on load. It requires an admin, returns the token and deletes the cookie, so it can only be read once. The token is shown in the page for copying into SPOTIFY_USER_REFRESH_TOKEN, as before.
  • The three logger.info lines that printed the token were removed. A response without refresh_token now redirects with ?error=no_refresh_token.
  • No migration, no new table: the token still lives only in env vars.

Automated evidence (passing)

  • app/api/spotify/callback/route.test.ts: redirect has no token; token is in an httpOnly cookie with the attributes above; the logger never receives the token; Spotify error → ?error=token_exchange_failed and no cookie; missing refresh_token; ?error=… and missing-code paths; Secure in production.
  • app/dashboard/admin/spotify-connect/actions.test.ts: token returned once and cookie deleted; null when there is no cookie; non-admin never touches the cookie.
  • Full npm test (389 suites), npm run lint (0 errors), npm run typecheck, npm run check:structure.

How to test manually (dev, after merge)

  1. Sign in as admin on a stack whose SPOTIFY_REDIRECT_URI points at the callback. Open /dashboard/admin/spotify-connect and click Connect Spotify.
  2. Approve on Spotify. Expected: the address bar shows …/spotify-connect?success=true and nothing else.
  3. Expected: the green card "Spotify connected!" shows SPOTIFY_USER_REFRESH_TOKEN=….
  4. DevTools → Application → Cookies: after the page loads, spotify_refresh_token_once is gone. While it existed it was HttpOnly.
  5. Reload the page (still ?success=true): the token card does not appear again.
  6. Browser history and the Vercel function logs contain no refresh_token.
  7. Edge cases: deny access on Spotify → red "OAuth error: access_denied" card. Sign in as a non-admin and open the page → redirected to /dashboard.
