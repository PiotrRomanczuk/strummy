What the real database showed that the mock could not

  • A teacher sees only their own ledger rows for a student shared with another teacher: teacher A's balance for A1 is 3, the student's own view is 5. The mock had no notion of who reads.
  • The "lesson held" ledger row comes from the real balance trigger (trg_lessons_sync_credit_entry) when the lesson is set to COMPLETED; the reads join it to the lesson date.
  • A parent of two children with different teachers sees, on one child's page, only that child's teacher's price list, although RLS lets the parent read both.
  • The duplicate-credit protection is the database's partial unique index, not app code: with 5 parallel calls every call returns success and exactly one +4 row exists.

How to test manually

  1. On the LAN (or Tailscale), with .env.local pointing at the dev stack: 
    npx jest -c jest.config.rls.ts lib/services/billing app/actions/__tests__/billing-purchases.rls.test.ts
    Expected: 2 suites, 30 tests passed; no "left N users behind" warning.
  2. Prove the suites can fail: in app/actions/billing-purchases.ts change if (creditError && creditError.code !== UNIQUE_VIOLATION) to if (creditError) and rerun. Expected: 2 failures (five simultaneous clicks, retry after success). Revert.
  3. Prove the CI gate: blank the keys and require the database: 
    RLS_REQUIRED=1 RLS_TEST_SERVICE_ROLE_KEY= SUPABASE_SERVICE_ROLE_KEY= SUPABASE_LOCAL_SERVICE_ROLE_KEY= npx jest -c jest.config.rls.ts lib/services/billing
    Expected: exit 1, "Got error running globalSetup … RLS_REQUIRED=1 but no RLS database credentials". The same command without RLS_REQUIRED=1: 11 skipped, exit 0 (unchanged local behaviour).
  4. Check the dev stack is clean afterwards: no auth users rls-*@guitarcrm.local from the run remain (global teardown sweeps by run id and fails the run if it cannot).

Limits

  • These suites run only where the dev database is reachable: the Mac on LAN/Tailscale and the self-hosted runner (rls job). GitHub-hosted ci.yml no longer exercises billing-purchases.ts.
