Chord review queue and empty-field fill (SNG-8, part 1) — manual test

Date: 2026-11-13 · Branch: feature/song-chords-verified (stacked on #1005) · verified in Chromium (Playwright) against the Mac local stack, a copy of dev with the 2026-11-13 chord-review run loaded

What was done

  • Data-quality rule song.chords-verified (validity, weight 2): applies to songs with chords whose review compared them with the recording; fails on conflict. A difference only song2logic analyze saw is check and never fails (it confuses major and minor). The quality query embeds the status of the song's chord-compare row (lib/data-quality/song-quality-record.ts).
  • Empty-field fill in the SNG-7 loader: chords from Chord ID's main chords, capo_fret only when Chord ID agrees with the sheet, key only when two independent sources agree and the chords are not written for a capo. Only null columns; each one listed in song_analyses.filled_fields; songs without a song_analyses row are not filled.

How to test manually

  1. Load a chord-review run into the dev stack (SNG-7 report), sign in as the dev admin, open /dashboard/admin/data-quality?rule=song.chords-verified → the conflicting songs are listed with the new rule.
  2. Fix one song's chords to what the recording plays, re-run song2logic chord-review and the loader → the song leaves the queue.
  3. Loader: --validateOnly prints fill:key / fill:chords / fill:capo_fret; after --commit each filled column is in song_analyses.filled_fields, and a second run fills nothing.
