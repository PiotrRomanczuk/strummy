Manual test: click-to-sort columns on admin/debug tables

Date: 2026-08-06

What was done

Added client-side, in-memory column sorting to every shadcn <Table>-based admin/debug table that previously had none. A new shared hook hooks/useSortableTable.ts tracks sort key + direction and re-sorts the already fetched rows; a new components/ui/sortable-table-head.tsx renders a clickable header with a sort-direction icon (unsorted / ascending / descending). Clicking a header once sorts ascending, clicking again flips to descending, clicking a different header switches to that column ascending.

Tables updated:

Table File Sortable columns
Import Logs components/admin/import-logs/ImportLogsTable.tsx Date, Song, Status
Student Health components/dashboard/health/StudentHealthTable.tsx Student, Health, Last Lesson, Lessons/Month, Overdue
AI Generation History components/ai/AIGenerationHistory.Table.tsx Type, Date
Recent AI Generations (debug) components/debug/AIGenerationsPanel.tsx Agent, Provider, Model, OK, Time
Rate Limits by Role (debug) components/debug/AIQueuePanel.tsx Role, Req/min
API Keys components/settings/ApiKeyManager.List.tsx Name, Created, Last Used, Status

Deliberately skipped: components/admin/logs/SystemLogsTable.tsx — it's an editorial log feed with no column headers at all (always newest-first, filtered via a server GET form), not a column-oriented table. Forcing click-to-sort there would require a structural rewrite inconsistent with its design.

Scope for this pass was the shadcn <Table> family only, per explicit choice — the DataList-based lists (Songs/Lessons/Assignments/Users) already have URL-param chip sorting and were left as-is.

How to manually test it

  1. Run npm run dev and sign in as the dev admin account.
  2. Visit /dashboard/admin/import-logs — click "Date", "Song", or "Status" in the header row. An up/down arrow appears on the active column; the row order changes; clicking the same header again reverses the order.
  3. Visit /dashboard/admin/debug, scroll to "Rate Limits by Role" and "Recent AI Generations" — same click-to-sort behavior on every header.
  4. Visit /dashboard/settings, scroll to "API Keys" — create two keys with names that sort differently (e.g. "Alpha Key", "Zebra Key") and confirm clicking "Name" toggles order.
  5. Visit any admin dashboard page with the Student Health table (e.g. an "at-risk students" or student health widget) — confirm the desktop table's headers are clickable and sort; the mobile card view re-orders too since it shares the same sorted list.

Edge cases checked

  • Empty tables (no rows) — no error, sort headers still render, no-op when clicked.
  • Null/undefined values (e.g. "Last Lesson: Never", empty error message) — nulls sort to the top consistently rather than throwing.
  • Switching sort column resets to ascending on the new column rather than carrying over the previous direction.
