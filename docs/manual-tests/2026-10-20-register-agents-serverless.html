Rejestracja agentów AI w bundlu serverless

Data: 2026-10-20 · Gałąź: fix/register-agents-in-serverless

Co zostało zrobione

Agenci AI są rejestrowani w rejestrze jako efekt uboczny importu @/lib/ai. Trasy, które importują tylko rejestr (szkic z nagrania, ekstrakcja akordów, normalizacja piosenek), w bundlu Vercela nigdy tej rejestracji nie uruchamiały, więc executeAgent kończył się błędem Agent not found. Na serwerze deweloperskim błąd był niewidoczny, bo inna trasa w tym samym procesie zdążyła już zaimportować @/lib/ai.

Nowy helper lib/ai/agents/ensure-registered.ts (ensureAgentRegistered(id)) rejestruje wszystkich agentów, jeśli żądanego nie ma w rejestrze. Wywołany przed executeAgent w trzech agentach. Test jednostkowy: ensure-registered.test.ts.

Obserwacja na produkcji przed poprawką

POST https://strummy.online/api/lessons/<lessonId>/transcript-draft
{"error":"Agent not found: lesson-transcript-draft","code":"generation_failed"}  HTTP 502

Jak przetestować ręcznie

  1. Po wdrożeniu na main wziąć lekcję z transkryptem (karta „Transkrypcja” na stronie lekcji) i w panelu kliknąć „Szkic z nagrania”, albo z klucza API nauczyciela: 
    curl -sS -X POST "https://strummy.online/api/lessons/<lessonId>/transcript-draft" \
  -H @~/.config/strummy/curl-auth-header -H "Content-Type: application/json" \
  --data '{"aliases":["Quentin"]}' -w '\nHTTP %{http_code}\n'
  2. Oczekiwane: brak komunikatu Agent not found. Odpowiedź 200 ze szkicem, albo 502 z błędem modelu (saldo OpenRouter, model) — to osobny problem konfiguracji, nie rejestracji.
  3. Edge case: piosenki → „Wyodrębnij akordy” (agent song-chord-extraction) na produkcji działa tą samą ścieżką; sprawdzić, że nie zwraca Agent not found.
