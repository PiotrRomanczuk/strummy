What was done

.github/workflows/nightly-e2e.yml gets its schedule: back (removed 2026-10-11). Four crons, all on the self-hosted e2e runner on uwh against the StrummyDevelopment stack (never production):

  • 01:17 UTC (03:17 Warsaw) — full device matrix (Desktop Chrome, iPhone SE, iPhone 17 Pro Max, iPad Pro, ~1 h). The only run allowed to open/update/close the nightly-e2e tracking issue.
  • 07:17 / 13:17 / 19:17 UTC (09:17 / 15:17 / 21:17 Warsaw) — every test, Desktop Chrome only (~8 min), so PR runs do not queue behind an hour-long matrix during the day. These never touch the issue: a green single-project run would otherwise close it over three untested device legs.

Every run (scheduled or dispatched) now appends the triage report (scripts/ci/nightly-e2e-report.mjs) to the job summary, so it is readable on the run page without downloading the nightly-report artifact.

How to test

  1. Merge; scheduled workflows fire only from main. The first day run is the next 07:17 / 13:17 / 19:17 UTC slot.
  2. Actions → Nightly E2E → the run: the Select projects job log says Daytime schedule (17 7 * * *): Desktop Chrome only; the matrix has one leg; the run summary shows the report with a Verdict: line.
  3. After 01:17 UTC: four legs, and the Nightly E2E failures issue is updated (red) or closed (green).
  4. Dispatch by hand (gh workflow run nightly-e2e.yml) still runs the full set and still does not write the issue.
  5. Negative: a day run must not change the issue — check its timestamps after 09:17 Warsaw.
