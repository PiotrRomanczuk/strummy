Manual test — Cron dispatcher consolidation

2026-07-23 · fix/cron-dispatcher-consolidation

What was done

vercel.json had 7 direct cron entries, but the reminder / monitoring / notification-queue jobs were only reachable through /api/cron/dispatcher, which was never scheduled — so in production they never ran. Six jobs were silently dark: lesson-reminders, assignment-due-reminders, assignment-overdue-check, process-notification-queue, sync-calendars, admin-monitoring.

The dispatcher already fans out in-process to every job (its list is a strict superset of the 7 direct crons). So the fix collapses the 7 entries into a single dispatcher cron: 

"crons": [
  { "path": "/api/cron/dispatcher", "schedule": "0 6 * * *" }
]

Net effect:

  • Turns on all 6 previously-dark jobs — reminders and monitoring now actually run.
  • Removes the duplication (7 jobs were firing directly and would double-fire once the dispatcher ran).
  • 1 Vercel cron slot (Hobby-plan friendly), 1 invocation/day, 0 GitHub Actions minutes — no repeat of the past Actions-minutes bill.
Prerequisite: CRON_SECRET must be set in the Vercel project env. It already is (the previous 7 crons authenticated with it). Vercel automatically sends Authorization: Bearer $CRON_SECRET to cron routes, which is exactly what verifyCronSecret() checks.

How to test it

  1. Locally (dev server running, CRON_SECRET in .env.local): 
    curl -s -H "Authorization: Bearer $CRON_SECRET" \
  http://localhost:3000/api/cron/dispatcher | jq
    Expect a JSON body with summary: {total, succeeded, failed} and a jobs[] array — every job listed with status: "success" (or a specific error string per job; one failing job never blocks the others — Promise.allSettled).
  2. Auth negative check: same curl with no / wrong bearer → 401 Unauthorized. Missing CRON_SECRET env → 500 CRON_SECRET not configured.
  3. In production after deploy: Vercel dashboard → project → Cron Jobs shows a single /api/cron/dispatcher entry; after 06:00 UTC its run log shows the fan-out JSON. Or hit it directly with the prod CRON_SECRET.
  4. Confirm the day-gated jobs: run on a Sunday → weekly-digest appears in jobs[]; Monday → weekly-insights; other days → neither.
