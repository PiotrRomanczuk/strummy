Repertoire becomes a table

2026-07-31 · branch feature/repertoire-table · shared DataList primitive

What was actually done

/dashboard/repertoire rendered a full editor card per song — title, status, an open notes textarea, five difficulty buttons and a Save button, stacked down the page. With 31 songs that is 31 textareas, 155 buttons and 31 hydrated client components, and the page could not be scanned at all.

It is now a table matching the Song Library: Title · Author · Stage · Last practised, one row per song. Notes and difficulty moved behind a per-row My notes toggle. Nothing was removed — every capability that existed still exists, one click further in, and only the opened row mounts an editor.

This was not a regression. The always-open editor shipped with the original repertoire feature (d0cda905, 2026-06-16) and there has never been a collapse toggle in the file's history. The compact list you may be remembering is the teacher-side student-detail repertoire, which has always been a row grid.

The shared primitive

Songs, Lessons and Assignments each had their own private copy of this layout — same card shell, same uppercase header strip, same ui-row grid, same mobile collapse — with three bespoke column strings, two different Card definitions between them, and one page using no card at all. Repertoire was not on the pattern at all.

components/shared/DataList.tsx is now the one list-table primitive, and Repertoire is built on it. Lessons and Assignments are untouched and still work — migrating them is a deliberate follow-up. The point of doing the extraction now was to stop Repertoire becoming a fourth private copy.

Two traps worth knowing about

1. Tailwind cannot see a class name built at runtime

The obvious implementation is md:grid-cols-[${'{'}template{'}'}] composed in JS. Tailwind's scanner only ever sees class names that appear literally in source, so that compiles to nothing and the grid silently never applies. The column template is passed as a --cols CSS custom property instead, with the responsive behaviour living in .ui-datalist-grid in design-tokens.css.

2. The page was outside the theme wrapper

Every ui-* rule in this app is scoped under .theme-strummy, and /dashboard/repertoire never had that wrapper — it was a plain max-w-2xl Tailwind shell. So the first version of this table rendered as a single stacked column with the headers jammed together, and typecheck and Jest both passed. Only screenshotting the running page caught it. The page now carries the theme wrapper and fonts like the Song Library does, which is also what makes the two look alike.

How to test it manually

Setup

cd ~/Desktop/MainCV/strummy
git checkout feature/repertoire-table
npm run dev

Sign in as the Student dev account (credentials in CLAUDE.local.md; Google SSO does not work against a LAN dev stack).

1 — The table

  1. Go to My Repertoire.
  2. expect one compact row per song under headers Title · Author · Stage · Last practised, with the whole list in a single bordered card on the ivory background.
  3. expect gone no open textareas, no difficulty buttons, no Save buttons visible anywhere on load.
  4. Open Song Library and flip back and forth. expect the two pages read as the same system — same card, same header strip, same row height, same serif italic titles.
  5. Click a song title — it still navigates to the song page.

2 — Notes and difficulty still work

  1. Click My notes on any row. The row highlights and the editor opens beneath it.
  2. Type a note, pick a difficulty, press Save. Expect a "Saved" toast, and the row collapses.
  3. Reload. Reopen the same row — expect the note and the selected difficulty are both still there.
  4. expect a row that has a saved note shows its toggle labelled Note in gold rather than My notes in grey, so a saved note is not invisible while collapsed.
  5. Open two different rows in turn — both work independently.

3 — Edge cases worth a look

  • Mobile / narrow (≤ 860px): the grid collapses to one column, the desktop cells hide, and each row shows a single meta line (author · stage · last practised). Check the toggle is still reachable and the editor still opens.
  • A teacher visiting their own /dashboard/repertoire: canEdit is false, so no toggle should render at all — just a read-only table.
  • Empty repertoire: the empty-state copy shows inside the card, with no header strip.
  • Never-practised song: Last practised shows an em dash, not a blank or "Invalid Date".
  • Dates: they must read Jul 23, 2026, not 23.07.2026. The explicit 'en-US' locale is deliberate — a bare toLocaleDateString() previously caused a server/client hydration mismatch on every row.

Follow-up

Lessons and Assignments still have their own copies of this layout. They work and are untouched here, but they are the remaining half of "all the list pages should look the same". Migrating each onto DataList is now a small change — supply columns and cells — and would also let the duplicate Card definitions in SongPrimitives and LessonPrimitives collapse into one.
