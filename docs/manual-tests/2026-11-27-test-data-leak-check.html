Test data: every spec deletes what it creates

Date: 2026-11-27 · Scope: Playwright and RLS test infrastructure, 15 specs. No application code.

What was done

The dev database had collected rows that tests created and nobody removed: 406 sign-in accounts without a profile, 343 API keys, 1 101 leads. Cleanup was a list of title and e-mail patterns, so a row named differently stayed.

  • Rule (.claude/rules/playwright-testing.md): the spec that creates a row deletes it, for real (not deleted_at), accounts through the sign-in account.
  • Check (tests/helpers/leak-check.ts): at the end of a run, before the pattern cleanup, it lists every row created since the run started that is still there: all tables of database.types.ts with id and created_at (49 today) plus auth.users. With E2E_LEAK_CHECK=strict a non-empty list fails the run: Core flows, the full E2E job, the nightly. The RLS suite runs the same check after its own sweep and always fails on a leftover.
  • Helper (tests/helpers/purge.ts): hard delete by the spec's unique token, by account, or by owner and time.
  • Specs fixed: see the table.

How to test

  1. Start the app against the dev stack: npm run build && npx next start -p 3300.
  2. Run a spec that creates rows: 
    E2E_PORT=3300 npx playwright test --config=playwright.remote.config.ts --project="Desktop Chrome" tests/e2e/settings/api-keys.spec.ts
    Expected at the end: 🧾 Leak check: nothing left behind.
  3. See it catch a leak: comment out the test.afterAll(() => purgeByToken('teacher_leads', …)) line in tests/e2e/smoke/for-teachers.spec.ts and run that spec. Expected: a warning listing teacher_leads with the address. With E2E_LEAK_CHECK=strict in front, the run exits non-zero. Delete the listed row afterwards.
  4. npm run test:rls: 310 tests pass and the teardown does not report leftover rows.
  5. npx jest __tests__/architecture/leak-check.test.ts: fails if the table list read from the generated types comes back empty.

Limits

  • The check works by time window on a shared database: a local run during a CI run shows up in that run's list. All CI jobs that write to dev share one runner and run one at a time.
  • Logs and queues written as a side effect (audit log, system logs, notification queue, AI call log) are not checked and still grow.
  • Rows left on dev before this change are not removed by it.
