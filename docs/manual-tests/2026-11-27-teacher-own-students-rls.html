Teachers see only their own students' quiz, skills and song-request data

Date: 2026-11-27 · Scope: one migration (20261127140000_teacher_own_students_side_tables.sql) and one RLS suite. No application code changed.

What was done

The staff policies on five per-student tables let every teacher reach every student's rows. They now let a teacher reach a row only when they teach that student (a non-deleted lesson together, teacher_teaches_student() — the same "Teaches" rule as the teacher_students view and the first half of may_teach_student()). Admins keep full access, students keep their own rows. None of the tables has a parent policy.

Table Teacher could before Teacher can now
chord_quiz_attempts read all read own students'
chord_srs read all read own students'
student_skills read + insert/update/delete all same, own students only
song_requests read + update (review) all same, own students only
song_status_history read all read own students'

The skills catalog (skills) is shared and unchanged.

What changes on screen

  • Song requests (/dashboard/songs/requests): a teacher's list shows only requests from students they teach. A request from a student with no lessons yet is visible to the admin only. Reviewing a request of someone else's student now changes nothing (the update matches no row).
  • Student detail pages (skills checklist, chord-quiz stats, song status history) look the same for the teacher's own students. Opening another teacher's student shows empty sections for these tables.
  • Admin and student views: no change.

How to test manually (dev stack)

  1. Apply the migration to StrummyDevelopment (already applied on 2026-11-27): 
    cat supabase/migrations/20261127140000_teacher_own_students_side_tables.sql | ssh elite 'docker exec -i supabase_db_StrummyDevelopment psql -v ON_ERROR_STOP=1 -U postgres -d postgres'
  2. npm run dev, sign in as the dev teacher, open /dashboard/songs/requests. Expected: only requests of students who have a lesson with this teacher (on dev today: none — the two seeded requests belong to demo students taught by someone else).
  3. Sign in as the dev admin, same page. Expected: every pending request.
  4. As the dev teacher open the dev student's profile → Skills. Expected: the checklist loads and a status change saves (the teacher teaches that student).
