Rename dev stack: StudentDevelopment → StrummyDevelopment

Date: 2026-10-20 · Branch: chore/rename-dev-stack

Co zrobiono

Stack Supabase dev na uwh został odtworzony pod nową nazwą na poziomie Dockera (10 kontenerów, nowa sieć, sklonowany wolumen 17 GB). Porty (5532x), klucze API i .env.local runnera są bez zmian. W repo każda żywa referencja do starej nazwy (workflow e2e.yml, scripts/e2e-remote/*, scripts/ops/*, CLAUDE.md, komentarze) wskazuje teraz supabase_db_StrummyDevelopment. Datowane dokumenty w docs/manual-tests, docs/analysis, docs/runbooks i zastosowane migracje zostały celowo nietknięte (historia). Runbook i rollback: infrastructure/docs/2026-10-20-strummy-dev-stack-rename.md.

Jak przetestować ręcznie

  1. Na uwh: docker ps --filter name=StrummyDevelopment → 10 kontenerów, healthy.
  2. curl -H "apikey: $KEY" http://192.168.1.75:55321/rest/v1/songs?select=id&limit=1 → 200 (klucz z ~/e2e/strummy/.env.local).
  3. Z Maca: npm run test:flows przeciwko dev stackowi albo poczekać na job E2E tego PR-a na self-hosted runnerze (używa nowych nazw przez scripts/e2e-remote/*).
  4. Migracja na dev: ssh uwh "docker exec -i supabase_db_StrummyDevelopment psql -U postgres -d postgres < plik.sql".
  5. Prod nie powinien drgnąć: 10 kontenerów StudentProduction Up, curl -sI https://strummy.online → 200.

Edge cases

  • Otwarte PR-y sprzed tej zmiany uruchomią scripts/e2e-remote/* ze starą nazwą i padną na docker exec, dopóki nie zostaną zrebase'owane na main.
