Date: 2026-11-15 · Scope: scripts/test-stack/stack/, scripts/test-stack/refresh.sh, migrate-db.sh test

What was done

  • StrummyTest runs on uwh (~/strummy-test, ports 573xx): db, auth, rest, realtime, kong, mailpit. No Studio and no postgres-meta (public /pg/* without a key — the incident found on production today). Images pinned to production's versions.
  • Own secrets, verified: anon and service_role are ES256, signed with the stack's own key; PostgREST trusts only that key and the stack's JWT secret (not the CLI defaults). Stored in Bitwarden.
  • refresh.sh: dump → API closed → wipe → auth data → public + strummy_ops → auth triggers → pending migrations → anonymisation → API open. A failure wipes the data and keeps the API closed (seen working on the first two attempts, which failed on FK order and schema ownership — both fixed).
  • migrate-db.sh accepts test.
